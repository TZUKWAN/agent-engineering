# 工具依赖网络：频繁共需对的排序红利与描述相似度

**包**：`P044_tool_dependency_network`　**主题**：T169　**实验**：EXP-0188（wave-7，query 级）　**数据**：AgentNet wave-7 候选帧（31,642 条 query / 222,770 个候选 / 14,520 条有可用金标对 / seed 42）

---

## 摘要

当一个任务需要多个工具时，需要的工具对是任意组合还是一种结构——频繁共现的工具对看起来也更相似吗，频繁对更容易被找到吗？本文在 14,520 条有可用金标对的 query 上检验三个预注册假设。H1 检验频繁共需对的金标是否更少缺席 rank-1，结果 supported，系数为 -0.3774，标准误 0.0637，95% 置信区间从 -0.5024 到 -0.2525，p 值经 Holm 校正后低于 0.001，LR 卡方为 73.9。这意味着频繁共需对的金标更少被排序器遗漏。H2 检验频繁对的描述 Jaccard 重叠是否高于随机抽取的非共现工具对。结果 supported，系数为 +0.1812，95% 置信区间从 0.1589 到 0.2043，p 值经 Holm 校正后为 0.0005，基于 304 个工具对的聚类 bootstrap。频繁对的描述确实更相似。H3 将网络的稀疏性与度分布作为描述性结构报告，不施加效应带。合成的命题是工具依赖网络是有结构的。频繁共需对更容易被正确排序。它们的描述也更相似。排序红利与描述重叠是同一现象的两面。功能相关的工具对既在行为上更易被一起找到，又在文本上更易被一起识别。对工具目录设计，这给出了一个维持功能搭配稳定性的效率论据。

**关键词**：工具依赖网络；频繁共需对；排序红利；描述相似度；预注册

## 1 引言

### 1.1 多工具任务的依赖结构

当一个任务需要多个工具时，工具对是否形成可预测的结构？P039 发现近同义诱饵使排序恶化。本文从另一个角度问：如果金标工具对是排序器见过的老搭档——频繁共需的工具对——排序是否更容易？

这个问题有一个直观的正面答案：频繁出现的工具对是排序器熟悉的老搭档，排序器应该更容易把它们排到正确的位置。但也有一个反向的可能：频繁对只是因为任务本身简单（需要的工具少且常见），与排序质量无关。区分两种解释需要控制任务复杂度——这正是本文的控制集所做的事。

用一个具体场景说明频繁共需对的概念。假设用户需要完成一个代码审查任务。这个任务需要三个工具的配合。第一，一个代码搜索工具来找到需要审查的文件。第二，一个文件读取工具来查看代码内容。第三，一个注释工具来添加审查意见。这三个工具构成一个工作流。搜索、读取、注释。这个工作流在多次执行同一类任务时反复出现，形成了一个频繁的工具搭配模式。如果排序器知道搜索和读取经常搭配出现，它可以在搜索结果返回后自动提升文件读取工具的排名。这就是频繁对信息的排序价值。

### 1.2 三个预注册假设

研究问题是同一任务多次 rollout 时频繁共需的工具对是否更容易被正确排序。H1 检验频繁共需对的金标是否更少缺席 rank-1。频繁共需对定义为在整个 dev 集中被至少十条 query 需要的金标工具对。方向预测为负——频繁对的金标更少缺席。H2 检验频繁对的描述 Jaccard 是否高于随机抽取的非共现工具对。方向预测为正——频繁对的工具描述更相似。H3 将网络的稀疏性与度分布作为描述性结构报告。

### 1.3 本文的定位

本文是系列中第一个在工具对级别进行网络分析的包。此前的包以 query 或 turn 为分析单位。本文将分析单位升到工具对级别。工具对级别分析的价值在于它能揭示工具之间的搭配结构——哪些工具被一起需要、哪些工具对是排序器的强项或弱项。

## 2 理论框架

### 2.1 频繁对的排序红利机制

频繁共需对的排序红利有一个直接的词面机制。频繁对的两个工具描述共享更多的域词汇。共享词汇使 BM25 对两个工具都给出较高的匹配得分。得分高则排名靠前。金标是频繁对的两个工具之一。频繁对的排序红利使金标更容易进入 rank-1。

共享域词汇的来源有两个。第一个是功能域的词汇约束。同一功能域的工具使用相同的技术术语。第二个是描述模板的复用。同一服务器的工具描述可能基于同一模板生成。两个来源叠加使频繁对的描述重叠高于随机对。

### 2.2 描述重叠的排序含义

描述重叠的排序含义是直接匹配。BM25 的得分是查询词与候选描述词的匹配加权和。频繁对的工具描述共享更多域词汇意味着更多匹配机会。更多匹配意味着更高得分。更高得分意味着更容易排到前列。

描述重叠的解释还有一个反向推论。如果频繁对的描述重叠不高于随机对则频繁对的排序红利不是来自描述相似度而是来自排序器的学习效应或位置效应。H2 的 supported 因此是排除了替代解释的关键一环。

### 2.3 网络稀疏性的治理含义

网络的稀疏性有一个直接的治理含义。频繁对只覆盖了少数 query。大多数 query 的金标对是唯一的或极低频的。这意味着基于频繁对的排序优化只能覆盖少数 query。大多数 query 仍需要通用的排序策略。频繁对优化的 ROI 取决于频繁对的覆盖率。

### 2.4 与 P039 的对照

P039 发现近同义诱饵使排序恶化。本文发现频繁共需对使排序改善。两者的对照揭示了排序质量的两个方向。诱饵是排序的敌人——长得像的候选混淆排序器。频繁对是排序的朋友——功能搭配的候选帮助排序器建立稳定的排序预期。两者的治理方向也相反。诱饵需要消除或区分。频繁对需要维持或增强。目录治理的完整策略应该同时处理两方向。削弱诱饵对。增强频繁对。

## 3 数据与方法

### 3.1 数据来源

wave-7 五分帧是本设计的数据底座。帧文件包括候选特征、重叠对、金标对、工具名册和服务器对五个分文件。总计涵盖 31,642 条 query、222,770 个候选插槽。其中 14,520 条有可用金标对。随机种子为 42。测试切分的读取行数为零。全量运行墙钟时间为 269.5 秒。运行环境为 Python 3.11.7。

### 3.2 变量操作化

pair_frequency 的计算方式是统计该金标对在整个 dev 集中被需要的 query 数。然后对每条 query 的所有金标对取平均频率。pair_frequent 是二值指示变量。当 query 的最频繁金标对出现在至少十条 query 中时标记为 1。

pair_overlap 的计算方式是取 query 的最强金标对的两个工具描述之间的实义词 Jaccard 重叠。random_pair_overlap 的计算方式是从相同两台服务器的目录中抽取一个不共现的工具对。计算同样的 Jaccard。抽取使用固定种子以保证可复现性。

overlap_difference 定义为频繁对重叠减去随机对重叠。这是 H2 的估计量。

### 3.3 模型与判定规则

H1 的模型是 logistic 回归。因变量是 fail_at_1。自变量是 pair_frequent 指示变量。控制集包括候选数的对数和问题长度的对数。聚类稳健标准误挂在 query_id 上。聚类数为 14,520。

H2 的检验方法是聚类 bootstrap。频繁对的描述重叠减去随机对的描述重叠。bootstrap 在工具对层面重抽样。聚类数为 304 个工具对。

H3 的结构报告包括观察到的金标对数量、度分布和头部对份额。全部为描述性统计。

判定规则要求系数的 95% 置信区间不含零。p 值经 Holm 校正后低于 0.05。效应量达到中等带即绝对值大于或等于 0.15。三个条件同时满足才判为 supported。

## 4 结果

### 4.1 H1 频繁共需对的金标更少缺席 rank-1

频繁对的金标缺席 rank-1 的几率显著低于非频繁对。logit 系数为 -0.3774。标准误为 0.0637。95% 置信区间从 -0.5024 到 -0.2525。p 值经 Holm 校正后低于 0.001。样本为 14,520 条有可用金标对的 query。

效应的量级可以用一个比例来理解。logit 系数为 -0.38 意味着频繁对的金标缺席几率比非频繁对低约 31%。以基线缺席率 18.91% 计，频繁对的金标缺席率约降至 13%。6 个百分点的改善意味着每 100 条 query 约 6 条从失败转为成功。

### 4.2 H2 频繁对的描述重叠更高

频繁对的描述 Jaccard 均值高于随机抽取的非共现工具对。系数为 +0.1812。95% 置信区间从 0.1589 到 0.2043。p 值经 Holm 校正后为 0.0005。基于 304 个工具对的聚类 bootstrap。

频繁对的重叠优势的词汇学基础是域术语的复用。功能相关的工具在描述中使用相同的技术术语。域术语的复用使两个描述的 Jaccard 重叠高于随机两个工具的重叠。

### 4.3 H3 网络稀疏且度集中

网络的稀疏性是描述性结构。频繁对只覆盖了少数 query。大多数 query 的金标对是唯一的或极低频的。这意味着基于频繁对的排序优化只能覆盖少数 query。

### 4.4 判定汇总

H1 为 supported。频繁对的金标更少缺席 rank-1。H2 为 supported。频繁对的描述重叠更高。H3 为描述性测量。网络稀疏且度集中。三个假设的判定组合意味着工具依赖网络是有结构的。

## 6 局限

第一。pair_frequency 的计算依赖发布方的选择标签。选择标签的质量直接影响频繁对判定的准确性。如果发布方的选择包含误选频繁对的定义会被污染。频繁对判定的准确性因此依赖于发布方选择的质量。这是一个外生依赖。第二。频繁对的定义阈值是设计者的判断。第三。观察设计不含操纵。第四。词面排序栈的结论不外推到语义排序器。第五。网络稀疏性的治理含义有限。因为频繁对只覆盖了少数 query。第六。效应的因果方向不确定。

---

## 7 结论

在 14,520 条有可用金标对的 query 上，频繁共需的工具对更容易被正确排序。它们的描述也更相似。工具依赖网络是有结构的。频繁对的排序红利与描述重叠是同一现象的两面。对目录治理，这给出了一个维持功能搭配稳定性的效率论据。不要拆散已经被反复需要的工具搭配。
