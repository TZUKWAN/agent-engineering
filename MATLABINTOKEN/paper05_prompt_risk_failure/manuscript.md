## 摘要

任务型交互智能体的失败可能源于用户提示本身的语用风险。本研究基于公开 AgentNet 数据集（xlangai/AgentNet）中的 22,532 条 GUI 任务轨迹，继承前三篇论文的提示语用特征，构建 10 项提示风险特征与 13 项推理/执行错误代理指标，采用 OLS 回归、Logistic 回归与 bootstrap 顺序中介分析，考察“提示风险 → 推理错误 → 执行错误 → 任务失败”的观察性统计路径。结果发现：（1）提示风险指数与推理错误指数呈正向关联（β = 0.021，p < 0.001）；（2）推理错误指数显著预测执行错误指数（β = 0.967，p < 0.001）；（3）执行错误指数与推理错误指数均显著负向预测任务完成（OR = 0.016、0.019，p < 0.001）；（4）顺序中介分析显示，提示风险通过推理错误与执行错误对任务完成的间接效应为负（间接效应 = -0.084，95% CI [-0.122, -0.045]）；（5）在完成标准缺失（β = 0.106，p < 0.001）和验证要求缺失（β = 0.190，p < 0.001）时，推理错误指数显著升高。研究仅使用公开现成数据，不调用大模型 API，且明确将结论限定为观察性统计路径，不构成因果证明。

**关键词**：任务型交互智能体；提示工程；提示风险；推理错误；执行错误；AgentNet

## 1. 引言

提示工程研究在过去两年迅速积累了“什么让智能体做得更好”的知识：角色设定、思维链、少样本示例、工具使用说明都被证明能提升任务表现。然而，工程实践的反面问题——**什么让智能体失败**——得到的关注却不成比例。失败分析通常以案例研究的形式出现，缺乏系统的变量化：我们很少能回答“一条指令携带多少风险、风险经由什么机制转化为失败”。

本研究把失败分析前移到指令侧，提出并检验一条可量化的观察性路径：**提示风险 → 推理错误 → 执行错误 → 任务失败**。路径的每一环都对应可规则化测量的变量：提示风险由十项语用特征加总；推理错误与执行错误是由推理文本和步骤标注构建的两个错误指数；任务失败即完成标签。检验这条路径的价值有二：对研究者，它把“提示质量”分解为可归因的中间机制；对实践者，它指出干预的最佳位置——不是笼统地“写好提示”，而是针对性补全缺失的验证与完成信息。本研究严格遵守数据边界：仅使用公开的 AgentNet 轨迹做二次分析，不调用任何大模型 API 生成新轨迹或新标注；所有统计结果来自真实数据；所有结论均表述为“关联”或“观察性统计路径”，不声称因果机制。

任务型交互智能体在执行用户指令时，常因提示表达不充分、结构不清或约束冲突而偏离目标。现有研究多关注模型能力、工具设计或训练数据质量，对用户提示如何诱发智能体失败的过程机制关注不足。本研究从语用学视角出发，将用户指令视为一种言语行为，考察提示中的风险特征如何通过显式推理链进一步传导为执行错误和任务失败。

前三篇论文已揭示用户提示中的操作显性度、约束密度和语用结构类型与智能体执行效果的关联。本研究进一步追问：**什么样的提示更容易让模型“推错”和“做错”**？这一问题不仅具有理论价值——有助于理解任务型交互中的失败传播机制，也具有实践价值——为提示设计提供风险规避依据。

## 2. 理论基础与研究框架

### 2.1 提示风险的概念

**提示风险**（prompt risk）指用户指令中可观测的语言特征，这些特征在既有研究与任务分析中被认为会增加智能体执行失败的概率。与“指令质量”这一笼统概念不同，提示风险强调三点：其一，风险是**可观测的语言事实**（某个必要成分是否缺失、某种冲突是否出现），而非对用户能力的评价；其二，风险是**分维度的**——验证缺失、约束缺失、指代不明等是不同的失败诱因，需要分开测量；其三，风险与失败的关系是**概率性**的——风险特征提高失败的先验概率，不决定单次任务的成败。这一概念化使提示风险可以脱离专家直觉、以规则化方式在大规模语料上测量，也与本文“无模型调用”的数据边界一致。

### 2.2 提示风险的十个维度

本研究将**提示风险**界定为用户指令中可能增加智能体理解难度、规划偏差或执行错误的语用属性。参考前三篇论文对提示语用特征的分类，本研究扩展出以下风险维度：

- **目标抽象**：指令只说明要做什么，未明确操作对象或目标状态；
- **对象缺失**：未指明操作对象；
- **完成标准缺失**：未说明任务完成判准；
- **约束缺失或过密**：完全没有约束词，或约束密度过高；
- **多子任务无顺序**：包含多个子任务但未给出操作顺序；
- **约束冲突**：同时出现“必须做”与“禁止做”的表述；
- **指代不明**：使用 it/this/that 等模糊指代；
- **初始状态缺失**：未说明当前环境状态；
- **验证要求缺失**：未要求检查、确认或验证。

### 2.2 推理错误与执行错误

**推理错误**指智能体在显式推理链中表现出的目标误解、约束遗漏、错误环境假设、任务分解不当、反馈后未修正、重复原策略、提前认为完成、缺少验证等偏差。**执行错误**指在环境中实际发生的错误工具/动作、无效操作、重复动作、失败终止、任务未完成等。两者均基于 AgentNet 轨迹文本和步骤级 `last_step_correct`/`last_step_redundant` 标签构建，属于代理指标而非人工精细标注。

### 2.3 观察性统计路径

选择“推理错误→执行错误”作为失败前传的原因是机制性的：智能体的行动序列由推理组织产生，推理中的目标误解与约束遗漏会投射到动作选择上；步骤级标注提供了这一投射的可观测痕迹。本研究检验的路径为：

```
提示风险特征 → 推理错误指标 → 执行错误指标 → 任务失败
```

该路径是**观察性统计路径**，用于描述变量之间的预测关系与过程证据，不声称因果机制。显式推理链作为中间变量，是本研究的核心分析对象，但仅指文本化推理痕迹，不等同于模型真实内部思维。

## 3. 数据与方法

### 3.1 数据来源

分析样本与系列前作一致：AgentNet 原始轨迹 22,625 行去重后 22,532 条任务（去重规则与审计见 `data/interim/paper05/dedup_audit.json`）。操作环境构成：win_mac 与 ubuntu 两个桌面环境；总体任务完成率约 78%。风险侧（prompt_risk_features）与错误侧（reasoning_execution_errors）按 task_id 内连接，进入路径模型的有效样本以各模型输出为准。

使用公开数据集 **AgentNet**（xlangai/AgentNet），原始轨迹文件 22,625 行，其中 93 行为重复 `task_id`（官方元数据 `meta_data_merged.jsonl` 为 22,532 条）；按官方 step_num 匹配优先、否则保留末次出现的规则去重后为 **22,532 条任务**、**416,186 个步骤**（审计见 `data/interim/paper05/dedup_audit.json`）。每个任务包含用户指令、任务完成标签、难度评分、操作系统以及轨迹步骤；每个步骤包含 `observation`、`thought`、`action`、`code`、`reflection`、`last_step_correct`、`last_step_redundant`。

### 3.2 提示风险特征

十项风险特征全部由正则与词表规则在指令文本上计算，可分三组。**缺失组**（5 项）检查必要的语用成分是否缺位：目标抽象（instruction 仅给高层目标而无具体对象/状态）、对象缺失（未指明操作对象）、完成标准缺失、约束缺失（全无约束词）、初始状态缺失；其中四项以“未命中任何相关词表”判定，约束缺失继承 Paper 02 的约束词表。**过载组**（2 项）检查语言成分的超量：约束过密（约束词密度超过样本 95 分位的任务）与约束冲突（“必须/只能”与“不要/不能”共存于同一指令）。**结构组**（3 项）检查组织缺陷：多子任务无顺序（多子任务且无序列连接词）、指代不明（it/this/that 等无明确先行词的指代）、验证要求缺失（全无验证类词汇）。三组划分直接对应路径模型的三类失败诱因：信息不足、信息过载、组织混乱。

继承前三篇论文的语用特征（`has_application`、`has_operation_object`、`has_target_action`、`has_target_state`、`has_file_reference`、`has_operation_order`、`has_multiple_subtasks`、`has_completion_criteria`、`has_initial_state`、`has_vague_reference`、`word_count`），并扩展构建风险特征：

| 风险特征 | 操作化定义 |
|----------|------------|
| goal_abstraction | 有目标动作但无操作对象且无目标状态 |
| object_missing | 无操作对象 |
| completion_standard_missing | 无完成标准词 |
| constraint_missing | 无约束词 |
| constraint_overdense | 约束密度 > 5% |
| multi_subtask_no_order | 有多子任务但无顺序词 |
| constraint_conflict | 同时出现要求型与禁止型约束 |
| vague_reference | 存在 it/this/that 等模糊指代 |
| initial_state_missing | 无初始状态描述 |
| verification_missing | 无明确验证动词 |

将 10 项风险特征加总得到 **risk_index**（提示风险指数）。

### 3.3 指标构建的构念依据

13 项错误代理指标按“发生在推理侧还是执行侧”分为两组，全部为二元指标（0/1），逐任务判定。**推理错误指数**（8 项）捕捉“想错了”，其判定规则均要求“坏结果 + 缺少正确行为”同时出现：`err_goal_misunderstanding`（任务未完成且推理含误解/不确定表述）、`err_constraint_omission`（指令含约束但推理零提及）、`err_wrong_env_assumption`（推理有假设但零验证）、`err_task_decomposition`（多子任务但推理零分解）、`err_no_correction_after_error`（有错误步骤但推理零自我修正）、`err_repeat_strategy`（有错误步骤且动作重复）、`err_premature_completion`（未完成但推理出现终止词）、`err_lack_verification`（指令含完成标准但推理零验证）。**执行错误指数**（5 项）捕捉“做错了”：`exec_wrong_tool_action`（存在错误步骤）、`exec_invalid_operation`（observation 含 error/invalid 等词）、`exec_repeated_action`（存在冗余步骤）、`exec_failed_termination` 与 `exec_task_incomplete`（任务未完成）。两组的划分依据是错误的可观察位置——前者只体现在推理文本与行为序列的对照中，后者伴随环境状态的直接改变。加总为指数而非逐项建模的理由是：单项发生率过低（部分不足 1%），指数在保留方差的同时稳定了测量。

**推理错误指标**（每项为二元 0/1）：

| 指标 | 操作化定义 |
|------|------------|
| err_goal_misunderstanding | 任务失败且 reason 或推理文本含误解/不确定性表达 |
| err_constraint_omission | 指令含约束词但推理文本未提及 |
| err_wrong_env_assumption | 推理文本含假设词但无验证词 |
| err_task_decomposition | 指令含多子任务但推理文本无分解词 |
| err_no_correction_after_error | 存在错误步骤但推理文本无自我修正表达 |
| err_repeat_strategy | 存在错误步骤且动作文本重复 |
| err_premature_completion | 任务失败但推理文本含终止词 |
| err_lack_verification | 指令含完成标准但推理文本无验证词 |

**执行错误指标**（每项为二元 0/1）：

| 指标 | 操作化定义 |
|------|------------|
| exec_wrong_tool_action | 存在 last_step_correct = False 的步骤 |
| exec_invalid_operation | observation 文本含 error/fail/invalid 等词 |
| exec_repeated_action | 存在 last_step_redundant = True 的步骤 |
| exec_failed_termination | task_completed = False |
| exec_task_incomplete | task_completed = False |

将推理错误指标加总得到 **reasoning_error_index**，将执行错误指标加总得到 **execution_error_index**。

### 3.4 分析方法

模型的因变量与链接函数按测量层次选择：推理错误指数与执行错误指数为近似连续的加总指数，用 OLS；任务完成为二值变量，用 Logistic 并报告 OR。控制变量的选择遵循系列统一口径（任务难度、指令词数中心化、操作系统），词数中心化以降低与风险特征的共线性——风险特征多与指令长度正相关。标准误为模型默认的非稳健标准误；作为补充，中介分析使用 bootstrap 重抽样（500 次）直接构造间接效应的百分位置信区间，避免对间接效应分布形态的正态假设。

1. **OLS 回归**：`reasoning_error_index ~ risk_index + controls`
2. **OLS 回归**：`execution_error_index ~ reasoning_error_index + risk_index + controls`
3. **Logistic 回归**：`task_completed ~ execution_error_index + reasoning_error_index + risk_index + controls`
4. **Logistic 回归**：`task_completed ~ risk_index + controls`（总效应）
5. **Bootstrap 顺序中介分析**：估计提示风险 → 推理错误 → 执行错误 → 任务失败的间接效应（500 次自助抽样）。

控制变量包括任务难度、指令词数（中心化）和操作系统。所有分析使用 Python 3，随机种子 42。

## 4. 结果

### 4.1 指数与特征分布

十项风险特征的发生率差异极大——从不足 1% 的“约束冲突”到超过 87% 的“验证要求缺失”。发生率的层级结构本身就是对用户书写习惯的刻画：用户默认智能体“自己看着办”，因此缺失型风险普遍存在，而过密与冲突型风险仅出现在少数精细撰写的指令中。

### 4.1 指数描述与提示风险特征分布

两项错误指数的总体水平：推理错误指数均值 0.626（SD 0.817），执行错误指数均值 2.141（SD 1.169）。风险指数均值 4.46（SD 1.17）。三个指数的分布均右偏，符合“多数任务正常、少数任务集中出错”的形态。

### 4.1.1 风险特征发生率

在 22,532 条任务中，主要风险特征的发生率如下：

| 风险特征 | 发生率 |
|----------|--------|
| 初始状态缺失 | 92.7% |
| 约束缺失 | 92.8% |
| 验证要求缺失 | 87.4% |
| 完成标准缺失 | 81.5% |
| 多子任务无顺序 | 36.3% |
| 指代不明 | 29.4% |
| 对象缺失 | 15.0% |
| 目标抽象 | 9.6% |
| 约束过密 | 0.9% |
| 约束冲突 | 0.1% |

提示风险指数的均值为 4.46（SD = 1.17）——按十项特征计分，一条典型指令天然携带约 4 项风险，这印证了 4.1.1 的层级判断：缺失型风险是 AgentNet 指令的常态而非例外。分布详见 `results/tables/single_risk_feature_to_reasoning.csv`。

### 4.1.1 风险特征谱的三个层级

发生率表揭示了一个清晰的层级结构。**第一层是“普遍缺失”**（发生率 80%–93%）：初始状态缺失、约束缺失、验证要求缺失与完成标准缺失——绝大多数用户指令只描述“要做什么”，而不说明“从什么状态开始”“不能做什么”“怎么算做完”。这一层级解释了风险指数均值为何高达 4.46：按十项特征的计分方式，一条“普通的”指令天然携带四到五项缺失型风险。**第二层是“结构性遗漏”**（15%–36%）：多子任务无顺序与指代不明——它们出现在较复杂的指令中，与任务复杂度共变。**第三层是“过密冲突”**（不足 1%）：约束过密与约束冲突是稀有事件。三层级的划分提示：提示风险的“常态”是缺失而非错误，干预的优先级应放在缺失型风险的补全上。

### 4.2 提示风险与推理错误

相关矩阵为路径的第一段提供了初步证据：风险指数与推理错误指数的相关为 0.016——非常接近于零。这一看似矛盾的相关（模型 1 的 β 显著）是控制变量的作用：风险指数与难度、词数近乎不相关，而错误指数与二者正相关；控制后风险的条件效应显现。逐特征的相关则更强：完成标准缺失、验证缺失与推理错误指数的相关在 0.10–0.15 之间。这提示：风险对错误的影响主要在“条件于任务属性”之后才显现，也说明控制变量的必要性。

### 4.2.1 提示风险与推理错误

OLS 回归显示，在控制任务难度、操作系统和指令词数后，提示风险指数显著正向预测推理错误指数（β = 0.021，SE = 0.005，t = 4.27，p < 0.001）。任务难度的效应不显著（β = 0.006，p = 0.149）。单独风险特征的效应见图 3。十项特征中有四项显著正向预测推理错误指数：完成标准缺失（β = 0.106，p < 0.001）、验证要求缺失（β = 0.190，p < 0.001）效应最大——验证与验收信息的缺失直接推高了推理中的错误标记率；而目标抽象、对象缺失等特征单独不显著，提示风险是“组合性”的：单项缺失可以被其他信息补偿，多项叠加时推理错误才显著抬升。这也为风险指数作为加总指标的构念效度提供了支持。

![图 3 单独提示风险特征与推理错误指数的关联](results/figures/fig3_risk_feature_effects.png)

单独风险特征的结果显示：

| 风险特征 | 系数 | 标准误 | p |
|----------|------|--------|---|
| 完成标准缺失 | 0.106 | 0.015 | < 0.001 |
| 验证要求缺失 | 0.190 | 0.017 | < 0.001 |
| 约束过密 | 0.122 | 0.061 | 0.045 |
| 约束缺失 | -0.038 | 0.022 | 0.086 |
| 其他特征 | 不显著 | — | — |

结果表明，**缺少完成标准**和**缺少验证要求**是与推理错误关联最强的两项风险特征。

### 4.3 推理错误与执行错误

模型 2 的估计显示，推理错误指数对执行错误指数的预测极强（β = 0.967，SE = 0.008，t = 114.5，p < 0.001）：控制提示风险、难度与平台后，推理侧每多 1 单位错误指标，执行侧错误指标平均增加约 0.97 单位。两个指数近乎 1:1 联动并非偶然——它们分别从 thought/reflection 文本与步骤标注两个观测面刻画同一执行过程的质量；这一强关联既支持“推理质量传导至执行质量”的路径假设，也提示两个指数共享方法方差，解读时应把二者视为同一质量维度的两个测量面，而非两个独立构念。

OLS 回归显示，推理错误指数显著正向预测执行错误指数（β = 0.967，SE = 0.008，t = 114.5，p < 0.001）。在控制推理错误指数后，提示风险指数对执行错误指数的直接预测作用不显著（β = 0.008，p = 0.176）。

### 4.4 执行错误、推理错误与任务完成

模型 3 以任务完成为因变量，同时纳入两条错误指数与全部控制（表见 `results/tables/model3_errors_to_completion.csv`）。执行错误指数（OR = 0.016，p < 0.001）与推理错误指数（OR = 0.019，p < 0.001）均与完成概率呈强负关联；提示风险指数的直接效应不显著（OR = 1.075，p = 0.117）。控制变量中，win_mac 平台完成率显著更低（OR = 0.263），任务难度与指令词数的效应方向为正但量级小。

必须正视本模型的统计性质：错误指数由步骤级监督信号（last_step_correct 等）聚合而成，与完成标签近乎共线，Logistic 拟合呈现**准完全分离**的特征——极小的 OR（0.016/0.019）、极大的截距（16.6）与天文数字级的 z 值（|z| > 14）都是分离的典型表现。因此模型 3 的 OR 值不应作为效应量解读，其价值在于确认方向：错误越多，完成越不可能。效应量的正确表达是相关矩阵中的量级（执行错误与完成的相关约 −0.61）与分组完成率差距。

Logistic 回归显示，执行错误指数（OR = 0.016，p < 0.001）和推理错误指数（OR = 0.019，p < 0.001）均显著负向预测任务完成。提示风险指数的直接效应在本模型中不显著（OR = 1.075，p = 0.117），这提示风险需通过错误中介变量才能充分体现其负面作用。执行错误指数按四分位分组后的完成率呈近乎断崖式下降：第一组（指数 ≤ 2，n = 15,719）完成率 99.1%；第二组（2 < 指数 ≤ 3，n = 3,630）71.1%；第三组（3 < 指数 ≤ 5，n = 3,183）完成率 **0.0%**。这一“断崖”是准完全分离的直接表现：执行错误指数超过 3 的任务无一完成。操作系统分组的完成率（win_mac 77.4%，ubuntu 79.0%）远不足以解释该梯度，错误指数本身才是主导变量。

#### 4.4.1 按执行错误指数四分位的完成率

把执行错误指数按四分位分组后，完成率呈断崖式梯度：

| 执行错误指数区间 | n | 完成率 |
|------------------|-----|--------|
| ≤ 2（第 1 四分位） | 15,719 | 99.1% |
| 2–3 | 3,630 | 71.1% |
| > 3 | 3,183 | **0.0%** |

最上四分位（指数 > 3）的任务**无一完成**。这一模式是 4.5 节准完全分离诊断的描述性来源：错误指数越过某一点后，完成在数据中不再出现。它同时给出一个极具操作价值的工程推论——执行错误指数可以作为任务运行时的**实时失败预警器**：指数升到 3 以上时，继续执行大概率只是浪费预算，触发回滚、求助或人工接管是更优选择。

### 4.5 风险特征对推理错误的进一步刻画

风险指数是十项特征的等权加总，隐含“各特征等价”的假设。单特征回归放松了这一假设（表见 `single_risk_feature_to_reasoning.csv`）：在十个特征中，完成标准缺失的效应最大（β = 0.106），其后依次为验证要求缺失（0.190）、约束过密（0.125）与约束冲突（0.279，不显著）。等权加总的风险指数仍然预测推理错误（β = 0.021，p < 0.001），说明指数作为一阶近似是可用的；但特征层面的异质性提示，未来的风险测量应按特征效应加权，而非简单求和。

### 4.5 总效应与顺序中介

模型 4 估计风险指数对任务完成的总效应：不显著（OR = 0.984，p = 0.306）。与模型 3 中直接效应亦不显著（p = 0.117）结合来看，风险指数对完成的全部作用都经由“推理错误 → 执行错误”的间接路径传导——这正是顺序中介分析要量化的对象。

Bootstrap 顺序中介分析（500 次重抽样）结果显示，提示风险经推理错误与执行错误传导至任务完成的间接效应为 **−0.084**（95% CI [−0.122, −0.045]），置信区间不包含 0，500 次抽样中间接效应为正的比例为 0%。三条证据（总效应零、直接效应零、间接效应为负且显著）组合成观察性数据所能提供的最强的“完全中介”模式：提示风险不直接改变完成概率，它通过诱发推理错误、进而放大执行错误来破坏任务完成。需要再次强调，中介分析在观察性数据上检验的是与路径图一致的统计模式，不构成对因果顺序的证明——理论上同样存在“容易的任务风险低且错误少”的混杂解释。

当以任务完成为因变量、仅纳入提示风险指数时，提示风险的直接效应不显著（OR = 0.984，p = 0.306），说明总效应较弱。观察性统计路径系数见图 2。

## 5. 讨论

### 5.1 风险特征的构念依据

十项风险特征并非任意罗列，每一项都对应语用学中的一个功能范畴：目标抽象对应言语行为理论中的“成事条件不明”；对象缺失与指代不明对应关联理论中的“指称确定失败”；约束缺失/过密/冲突对应合作原则中“量”与“方式”准则的失衡；多子任务无顺序对应“方式”准则中的顺序性缺失；初始状态缺失对应共同基础（common ground）建立不足；验证要求缺失对应终止判准的缺位（Paper 01）。因此风险指数是这些功能范畴的加总，而非一份随意的清单。

“风险经由错误传导”的机制可以在三个认知环节上定位。**理解环节**：目标抽象、对象缺失、指代不明直接增加指令解析的歧义，使智能体在首个推理块中就可能锁定错误的目标表征——推理错误指数中的“目标误解”项即该环节的标记。**规划环节**：约束缺失或约束冲突使智能体在生成动作序列时缺少边界检查，规划出的路径可能可行但不合规；多子任务无顺序则使规划的步骤间依赖缺失。**终止环节**：完成标准与验证要求缺失使智能体缺少“停止前核对”的触发器——这正是 Paper 01 的“终止判准”缺失形态；其在数据上的表现是推理含终止词但任务未完成（premature_completion 指标）。三个环节中，理解与规划的失败累计为推理错误指数，终止失败集中体现为执行错误指数与完成标签——这一分解恰好对应本文模型 1（风险→推理）与模型 2/3（推理→执行→完成）的两段式设计。

本研究发现，提示风险并非直接决定任务失败，而是通过推理错误和执行错误逐步传导。高风险提示（尤其是缺少完成标准和验证要求）容易导致智能体在显式推理链中遗漏关键判准，进而增加执行偏差。传导的微观机制可以从言语行为理论推导：完成标准缺失意味着指令缺少“成事条件”（felicity condition）的明示——智能体必须自行构造一个验收判据；构造质量随任务而异，构造失败即表现为推理错误（在推理文本中出现误解、假设无验证等标记），继而外化为执行错误。风险指数本身不显著影响完成（模型 4），恰与该机制自洽：风险是“推理出错”的诱因，不是“任务失败”的直接原因。

### 5.2 约束维度的方向对比

逐特征的方向对比中最有意思的是约束维度：约束缺失与推理错误呈负向关联且处于边缘水平（β = −0.039，p = 0.084），而约束过密呈显著正向（β = 0.125，p = 0.039），约束冲突方向为正但未达显著（β = 0.279，p = 0.126，发生率仅 0.1%）。结合 Paper 02 的发现——约束密度与完成率在高难度任务中呈倒 U 形——本文的数据进一步说明：约束过密不仅降低完成率，还伴随更多推理错误；而约束缺失在简单任务中无害甚至略优。约束的语用功能具有明确的条件性：适量是边界资源，过密是认知负荷，缺失在简单任务中可被任务简单性补偿。

### 5.3 逐特征机制的讨论

逐特征的方向对比中最有趣的是约束维度：**约束缺失**与推理错误指数呈负向关联且处于边缘水平（β = −0.039，p = 0.084），而**约束过密**呈显著正向（β = 0.125，p = 0.039），**约束冲突**的方向为正但未达显著（β = 0.279，p = 0.126，发生率仅 0.1%）。结合 Paper 02 的发现——约束密度与完成率在高难度任务中呈倒 U 形——本文的数据进一步说明：约束过密不仅降低完成率，还伴随更多推理错误；而约束缺失在简单任务中无害甚至略优。约束的语用功能具有明确的条件性：适量是边界资源，过密是认知负荷，缺失在简单任务中可被任务简单性补偿。

### 5.2.1 模型 1 与模型 2 的逐项解读

模型 1 中除风险指数外，控制变量的表现值得注意：任务难度不显著（β = 0.006，p = 0.149），说明推理错误更多由指令的语言属性而非任务客观复杂度驱动；win_mac 平台的推理错误显著更低（β = −0.141，p < 0.001），与 Paper 01/02 中该平台完成率更低的方向相反，提示平台对“推理质量”与“任务成败”的影响方向可以不一致——这正是错误指数作为中介变量的价值所在。

模型 2 中推理错误指数的系数接近 1（β = 0.967），即推理侧每多 1 单位错误，执行侧错误几乎等量增加。两个错误指数由不同观测面（推理文本 vs. 步骤标注）构建，系数如此接近 1 说明“想错”与“做错”在数据上高度同步，为“推理—执行”传导路径提供了最强的一条证据。

### 5.3 逐特征机制的讨论

四个显著或边缘显著的特征值得逐个讨论。**验证要求缺失**（β = 0.190）是效应最大的风险项：没有验证要求的指令，智能体的推理中缺少“终止核对”环节，错误在未被检查的情况下累积。这与 Paper 01 的发现互为镜像——验证信息的存在降低终止偏差，其缺失则放大执行错误。**完成标准缺失**（β = 0.106）位居第二：与验证缺失相比，完成标准缺失更隐蔽——它不直接指向检查动作，而是让整个任务的目标状态模糊，推理的每一步都缺少“向哪里收敛”的参照。**约束过密**（β = 0.125）的效应方向与 Paper 02 的条件性倒 U 形一致：过密约束意味着执行时要逐项核对边界，任何一步的疏漏都计入错误。**初始状态缺失**不显著（β = 0.003）值得一提：说明智能体在多数任务中能够自行探测初始状态，“从零开始”并不必然诱发错误——这对提示建议的优先级有直接含义：先补验证与完成标准，初始状态可以后置。

### 5.4 理论与实践启示

理论上，本研究将前三篇论文的“用户侧”语用分析延伸到“智能体侧”的错误机制，形成了更完整的“表达—推理—行动—结果”分析链。结合逐特征与中介结果，提示设计应按优先级注意以下五点：

1. **明确完成标准或验证动作**——这是效应最大的两项风险（β = 0.106/0.190），且直接作用于终止环节；
2. **多子任务给出顺序**——虽单项效应不显著，但顺序缺失与结构化分解的缺失叠加时会放大推理错误；
3. **避免约束过密与约束冲突**——约束过密显著推高推理错误（β = 0.125），冲突方向为正但因发生率低（0.1%）功效不足；
4. **复杂任务适当提供初始状态信息**——总体不显著（β = 0.003），但高复杂度子样本可能不同；
5. **把风险清单前置到指令评审环节**——本文的十项特征均可由正则实时计算，适合做成指令输入的“风险提示器”。

### 5.4 局限与未来方向

第一，推理错误与执行错误指标均为规则型代理指标，可能遗漏语义层面的错误——例如“推理内容与任务无关”这类错误不在 13 项指标的覆盖范围内。第二，AgentNet 的 `thought`/`reflection` 是轨迹中记录的解释文本，不等同于模型真实内部思维。第三，本研究为横断面观察性设计，无法确立因果顺序；风险特征、错误与完成共享任务层面的混杂（复杂任务风险高、错误多、完成少），中介分析在观察数据上只能验证路径模式的一致性。第四，bootstrap 重抽样为 500 次，百分位置信区间在样本量两万级时已足够稳定，但对极端分位区间的估计仍偏粗。未来可结合实验操纵提示风险、引入过程标注数据集，或以多智能体平台做跨语料验证，检验本文“风险—错误—失败”路径的外推性。

## 6. 结论

本研究基于 AgentNet 数据，构建了提示风险、推理错误与执行错误的多维指标体系，并通过回归与 bootstrap 中介分析揭示了“提示风险 → 推理错误 → 执行错误 → 任务失败”的观察性统计路径。主要结论有四：其一，提示风险与任务完成无直接关联（模型 4 OR = 0.984，p = 0.306），其作用完全经由错误路径间接传导（顺序中介 −0.084，95% CI [−0.122, −0.045]）；其二，缺失型风险是 AgentNet 指令的常态（验证缺失 87.4%、完成标准缺失 81.5%），其中验证要求缺失对推理错误的影响最大（β = 0.190）；其三，约束维度呈条件性——缺失无害甚至略优、过密有害；其四，错误指数与完成之间的准完全分离要求把模型 3 的 OR 值读作方向证据而非效应量。

这些发现为理解任务型交互智能体的失败机制提供了过程证据，也为提示设计提供了可操作的改进方向：先补验证与完成标准（效应最大的两项缺失），再控制约束过密，最后在复杂指令中显式给出子任务顺序。与系列研究合观，四篇论文从验证（Paper 01）、约束（Paper 02）、推理结构（Paper 04）、风险路径（本文）四个侧面共同建立了一个可测量、可复核、可指导实践的指令语用学工具箱；把这套工具箱接入智能体的实时提示评审与自我核验机制，是下一阶段的自然目标。
