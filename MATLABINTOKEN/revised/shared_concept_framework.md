# 共享概念框架：任务型交互智能体

## 1. 核心概念界定

**任务型交互智能体（task-oriented interactive agent）** 是指能够根据自然语言任务指令，在外部可反馈环境中执行多步行动，并依据环境反馈进行调整、验证和终止的智能体系统。与通用对话系统不同，任务型交互智能体的核心特征在于：

- **目标导向性**：以完成用户指定的具体任务为最终目标；
- **行动序列性**：需要在环境中产生可观察的操作序列；
- **反馈依赖性**：依赖环境状态反馈进行规划修正；
- **终止判准需求**：必须明确何时停止操作并返回结果。

该概念在理论层面可覆盖 GUI Agent、TUI Agent、Web Agent、Code Agent 和 Tool-use Agent 等多种形态。不同形态的差异主要体现在环境接口（图形界面、终端、浏览器、代码解释器、工具 API），但其核心链路具有高度一致性。

## 2. 通用执行链路

本组论文采用统一的任务执行链路作为分析框架：

```
用户任务表达 → 任务表征 → 行动规划 → 环境操作 → 反馈修正 → 结果验证 → 执行终止
```

各环节的语用功能如下：

| 环节 | 语用功能 | 用户指令可提供的信息 |
|------|----------|----------------------|
| 用户任务表达 | 用户将目标转化为自然语言 | 任务目标、上下文、约束 |
| 任务表征 | 智能体理解任务并形成内部表示 | 动作、对象、状态、顺序 |
| 行动规划 | 将任务表征转化为操作序列 | 操作顺序、子任务分解 |
| 环境操作 | 在环境中执行具体操作 | 应用、文件、对象属性 |
| 反馈修正 | 根据环境反馈调整计划 | 错误处理、条件判断 |
| 结果验证 | 检查是否满足完成标准 | 完成标准、验证动作、目标状态 |
| 执行终止 | 停止操作并返回结果 | 终止判准、停止线索 |

## 3. 经验边界

本组三篇论文均使用 **AgentNet GUI 交互轨迹数据集** 作为经验基础。AgentNet 数据主要覆盖桌面 GUI 环境（Windows、macOS、Ubuntu），任务类型、用户群体与交互界面均具有特定性。因此：

- 研究结论应谨慎推广到 Web Agent、Code Agent 或 Tool-use Agent 等其他环境；
- GUI 环境的视觉-动作耦合特征可能使某些语用线索（如文件引用、应用名称）的权重高于其他环境；
- 跨平台、跨任务类型、跨用户群体的验证是未来研究的必要步骤。

## 4. 三篇论文在共享框架中的位置

| 论文 | 关注链路环节 | 核心语用问题 | 理论贡献 |
|------|--------------|--------------|----------|
| Paper 03 | 用户任务表达 → 任务表征 | 用户如何将任务组织为可执行的交互结构？ | 语用结构类型学 |
| Paper 02 | 行动规划 → 环境操作 | 用户约束如何调节智能体的行动空间？ | 约束收益—负荷边界 |
| Paper 01 | 结果验证 → 执行终止 | 用户如何为智能体提供停止线索？ | 完成标准作为终止判准 |

三篇论文共享同一经验数据，但研究问题、核心构念与分析目标各不相同，形成“任务组织—行动约束—终止判准”的完整分析链条。
