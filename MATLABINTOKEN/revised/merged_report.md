# 用户指令语用特征对任务型交互智能体执行效果的影响

## —— 基于 AgentNet 大规模 GUI 交互轨迹数据的实证研究三部曲

---

## 综合摘要

本研究报告由三项递进式实证研究构成，均基于 AgentNet 大规模 GUI 交互轨迹数据集（去重后原始样本 $N=22{,}532$，回归分析样本 $N=20{,}205$），从语用学视角系统考察用户指令的语言特征如何影响任务型交互智能体的执行效果。三项研究分别聚焦于三个逐层递进的分析层次：

**研究一（层次一：单一语用成分的存在/缺失）** 将用户指令中的完成标准/验证条件重新概念化为智能体的"终止判准"，检验了验证信息与任务完成率和执行步数的关联。结果支持：含完成标准的任务完成率显著更高（OR = 1.255, $p<.001$），执行步数显著更少（IRR = 0.883, $p<.001$），终止阶段冗余与错误亦更低。

**研究二（层次二：语用成分的密度/剂量效应）** 将约束密度界定为"条件性边界资源"，通过三阶段建模揭示了约束密度与完成率之间不存在全局倒 U 形关系，但在高难度和长指令等复杂条件下呈现显著倒 U 形模式，最优密度约 1.7%–1.9%。

**研究三（层次三：整体语用结构类型）** 将分析单元从单一成分提升至整体语用结构，利用潜类别分析（LCA）从 11 个二元语用特征中识别出五类用户指令语用结构类型，并验证了各类别在完成率、过程指标和路径稳定性上的系统性差异。

三项研究共同构建了一个从"成分"到"密度"再到"结构"的三层次分析框架，核心论点是：指令效果 = f (语用成分剂量, 语用结构类型, 任务复杂度)。

**关键词：** 任务型交互智能体；用户指令；语用特征；完成标准；约束密度；语用结构类型；潜类别分析；执行终止；认知负荷；AgentNet

### 1 引言

#### 1.1 背景：终止是被忽视的一环

以大语言模型（Large Language Model, LLM）为核心、融合视觉感知的任务型交互智能体，已在网页浏览、自动化办公与数字助手等场景快速落地：Mind2Web（Deng et al., 2023）、WebGPT（Nakano et al., 2021）与 AUSTIN（Yuan et al., 2023）展示了完整的“理解—规划—操作”能力，而 AgentNet（Wang et al., 2025）等大规模真实交互轨迹数据集的发布，使从数据角度研究这些能力的语言条件成为可能。

把智能体的一次执行抽象为一条链：**用户任务表达 → 意图解析 → 动作规划 → 环境交互 → 状态评估 → 执行终止**。在这条链上，研究与工程注意力高度集中于中段的规划与操作；然而决定一次执行最终成败的，常常是链的末端——智能体必须判断当前状态是否已经足够接近目标，并据此停止。终止环节处理不好，规划再好也会以失败或浪费收场。

#### 1.2 问题：终止不确定性及其两极偏差

与文本生成中“生成到句末即停”不同，任务型智能体的停止必须依赖对外部状态是否达标的判断。当指令只给出高层目标（“整理桌面”）而不给出判据（“截图全部移入 Screenshots 文件夹且桌面剩余不超过 5 个文件”）时，智能体面对的是一种结构性的**终止不确定性**（termination uncertainty）。它表现为两种对立偏差：

1. **提前终止**（premature termination）：目标未达成即停止，任务失败；
2. **过冲探索**（overshooting）：缺乏判据时反复验证、冗余搜索，步数超出必要。

这自然引出本文的核心问题：**用户指令中的何种语言信息，能为智能体提供可靠的停止信号？**

#### 1.3 论点与研究问题

我们提出：用户指令中的完成标准与验证条件（“检查/确认/确保……”“……即为完成”）正是这样一种信号——它们把开放目标转译为**可执行的停止条件**（executable stopping condition）。据此，核心研究问题是：当指令显式包含验证表述或目标状态时，智能体是否与更高的完成率、更少的执行步数以及更干净的终止过程相关联？

本文的基本论点是：**明确的验证标准降低了智能体对“是否已达目标”的不确定性，从而同时抑制提前终止与过冲探索。** 需要在起点处即明确：本文分析观察性交互轨迹，全部结论为统计关联而非因果效应；“终止判准”是对语言信息功能的刻画，而非对智能体内部机制的断言。

### 2 理论基础与研究假设

三条理论线索交汇于同一推论：完成标准是指令语力中承载验证信息的成分，它降低状态评估的认知成本，并为内部终止规则提供语言基础。

#### 2.1 言语行为理论：验证是指令语力的构成成分

言语行为理论（Austin, 1962; Searle, 1969）指出语言不仅描述世界，也执行行为。任务指令是典型的**指令式言语行为**（directive speech act）。细看其内部结构：当指令包含“检查”“确认”“确保”时，用户在指示操作之外同时规定了**验证行为**——要求把当前状态与目标状态比较并判断；当指令出现“完成”“正确”“就绪”时，用户直接给出了终止执行所需的**目标状态**。因此，完成标准并非指令的修饰成分，而是指令语力的构成部分，直接划定了任务的边界与停止时机。

#### 2.2 关联理论：认知经济的两端收益

关联理论（Sperber & Wilson, 1995）认为交际以最小认知努力换取最大认知效应。明确的完成标准同时改善两端：它免去智能体从模糊目标推断停止条件的成本（努力端），又让验证动作直接产生可观测的状态证据（效应端）。由此预期：含完成标准的指令与更少步数、更高完成率相关联。但关联理论同时内含一个开放问题——若验证信息过量，其约束可能挤占推理灵活性，使正向效应衰减甚至逆转，即密度与结果之间可能存在非线性。

#### 2.3 停止规则理论：内部终止 vs. 外部启发式

停止规则研究区分**内部终止**（达到预设目标状态即停）与**外部终止**（超时、干预等信号触发）（Gigerenzer et al., 1999; Payne et al., 1993）。完成标准为智能体提供了内部终止规则的语言线索；缺乏完成标准时，智能体只能依赖“步数够多了”“状态很久没变”一类启发式——这类规则不参照任务目标状态，容易滑向过冲或提前终止。

#### 2.4 假设

**H1a（完成率）** 含完成标准的任务完成率显著更高。
**H1b（执行效率）** 含完成标准的任务执行步数显著更少。
**H1c（终止过程）** 含完成标准的任务在终止阶段冗余比例与错误比例更低。

H1a–H1c 是核心假设，共同检验“终止判准”框架的基本预测。以下三个为限定范围的补充假设，其检验力受数据分布约束，结果按各自条件解读：

**H2（验证类型差异，探索性）** 不同验证语言形式（V1 动词指令式 / V2 状态目标式 / V3 条件验证式 / V4 混合式）的影响存在差异——类型分布严重失衡，仅作描述。
**H3（密度非线性，补充性）** 验证关键词密度与完成率可能呈倒 U 形。
**H4（位置效应，探索性）** 验证表述位于指令不同位置时效应不同。

### 3 研究方法

#### 3.1 数据与样本口径

数据来自公开的 AgentNet 数据集（Wang et al., 2025）：22,532 条自然语言 GUI 任务及完整交互轨迹，真实人机/人–智能体交互的观察性记录，非实验操纵数据。原始轨迹文件含 93 个重复 `task_id`，按官方元数据的 step_num 匹配优先、否则保留末次出现的规则去重（审计见 `data/interim/dedup_audit.json`）。任务完成状态、步骤正确性与冗余性字段来自数据集原始标注。

分析样本分四个层次，结论适用范围依层划定：

1. **原始全量样本**（$N=22{,}532$）：总体分布与完成标准标注；
2. **含完成标准原始子集**（$n=2{,}869$）：验证语言形式分类描述；
3. **回归分析样本**（$N=20{,}205$；剔除 `task_completed` 与 `task_difficulty` 缺失；其中含完成标准 $n=2{,}660$，不含 $n=17{,}545$）：所有回归模型；
4. **位置分析样本**（$N=2{,}491$）：含完成标准且验证关键词可定位。

#### 3.2 变量操作化

**核心解释变量**为二值的 `has_completion_criteria`（是否含完成标准/验证条件），由关键词与句法启发式规则提取。需明确其边界：规则化标注存在误报与漏报——部分完成标准表述可能未命中关键词，部分关键词在特定语境中并不表达完成判据。因此本文将其视为**一种可观测的语言线索**，而非“指令质量”的全面度量。

对含完成标准的指令，按关键词与句法窗口规则细分五类：

- **V1 动词指令式**：`check` / `verify` / `confirm` / `validate` / `ensure` / `make sure` 等，直接指示验证动作；
- **V2 状态目标式**：`done` / `complete` / `correct` / `proper` / `finished` / `ready` 等，描述目标状态；
- **V3 条件验证式**：`until` / `when` / `once` / `after` 等条件词；`until` 直接计入，其余仅当 15 词窗口内出现 V1/V2 关键词时计入；
- **V4 混合式**：同时命中至少两类；
- **V0 不可分类/伪阳性**：标注为 1 但未命中任何关键词。

**验证密度** `verification_density` = 验证关键词次数 / 指令总词数。**验证位置**按字符相对位置分三段：< 0.25 为开头，0.25–0.75 为中间，≥ 0.75 为末尾。

**因变量**：`task_completed`（0/1）、`total_steps`（计数）及终止阶段指标（3.3 节）。
**控制变量**：`task_difficulty`（1–10 连续评分）、`word_count`、`os`（ubuntu / win_mac）。

#### 3.3 终止阶段过程指标

为把“终止”从结果变量转为过程变量，基于步级标注计算六组指标：

1. **最后 25% 步冗余比例**（`last25_redundant_prop`）：最后 25% 步（向上取整，至少 1 步）中 `last_step_redundant == True` 的比例；
2. **最后 25% 步错误比例**（`last25_incorrect_prop`）：同上，`last_step_correct == False` 的比例；
3. **最后一步冗余/错误**（`final_step_redundant` / `final_step_incorrect`）：二值；
4. **最后 25% 步是否出现冗余/错误**（`last25_any_redundant` / `last25_any_incorrect`）：二值；
5. **异常短轨迹**（`abnormal_short`）：未完成任务中总步数不超过已完成任务第 5 百分位（本数据为 9 步）者，作为提前终止失败的描述性指标。

逐任务指标存于 `revised/paper01_tables/terminal_phase_metrics_by_task.csv`，分组汇总与组间比较分别存于 `terminal_phase_summary_by_criteria.csv` 与 `terminal_phase_group_comparisons.csv`。

#### 3.4 分析模型

- **完成率**：Logistic 回归，报告 OR 与 95% Wald CI；
- **执行步数**：负二项回归（NB2），报告 IRR、95% CI 与离散参数 alpha；
- **密度非线性**：Logistic 中加入密度二次项，AIC 与似然比检验（LRT）比较线性/二次模型；
- **位置效应**：卡方检验 + Bonferroni 校正的成对比例 Z 检验；
- **终止阶段指标**：连续比例用 Welch t 检验，二值指标用双比例 Z 检验。

全部分析在 Python 中实现，显著性水平 α = 0.05。所有系数按条件关联解释。

### 4 结果

结果按“结果层 → 总量层 → 过程层”组织：4.2 报告完成率，4.3 报告执行步数，4.4 报告终止阶段过程指标；4.5–4.6 为两个限定范围的补充检验（密度、位置），4.7 为稳健性。

#### 4.1 描述性统计与验证类型分布

回归样本（$N=20{,}205$）总体完成率 79.13%。不含完成标准的任务（$n=17{,}545$）完成率 78.63%，平均 18.92 步（SD 9.23）；含完成标准的任务（$n=2{,}660$）完成率 82.41%，平均 18.84 步（SD 7.96）——原始差异约 3.8 个百分点，方向与理论预期一致；其是否独立于难度、长度等混淆变量，交由回归判定。

验证语言形式的分布见表 1，其显著特征是**极端失衡**：动词指令式（V1）占 82.9%，混合式（V4）占 9.7%，不可分类（V0）占 7.1%，而状态目标式（V2，0.2%）与条件验证式（V3，0.0%）几乎不存在。这意味着 H2 不具备组间推断力，仅作描述；该失衡也提示规则化标注对 V1 类动词更敏感。

#### 4.3 完成标准与执行步数（H1b）

负二项回归结果见表 3。控制协变量后，含完成标准任务的预期步数低约 7.4%（IRR = 0.926，95% CI [0.912, 0.941]，$p<.001$），H1b 获得支持。难度每增加 1 分预期步数增加约 16.4%（IRR = 1.164，$p<.001$）；win_mac 与 Ubuntu 差异不显著（IRR = 1.015，$p=.069$）；离散参数 α = 0.086，表明适度过度离散、NB2 优于 Poisson。

值得注意的是 4.2 与 4.3 的组合含义：完成标准同时伴随“更多完成”与“更少步数”——更高的产出并没有以更多的执行投入为代价，这与“终止判准降低终止不确定性”的机制预测一致，而非单纯的“多写要求 → 做得更多”。

模式清晰：含完成标准任务在最后 25% 步的冗余比例、错误比例、出现冗余/错误的概率上均显著更低，未完成任务的异常短轨迹率（≤ 9 步）近乎减半（1.02% vs. 2.08%，$p<.001$）——后者是 H1c 中与“提前终止”最直接对应的证据。相比之下，最后一步的冗余率与错误率在两组间无差异（$p=.620$ / $p=.929$），且绝对水平极低。

综合三条证据链，H1c 获得部分支持：完成标准的关联集中体现在终止阶段的**分布性指标**（最后 25% 步的冗余/错误水平、异常短轨迹率），而非最后一步的点事件。再次强调，这是共变关系而非因果效应。

#### 4.5 验证密度：线性而非倒 U（H3，补充性）

密度二次项检验不支持倒 U 形：线性模型中 `verification_density` 系数为正（OR = 77.422，$p=.036$）；二次项不显著（OR = $5.0\times10^{-6}$，$p=.606$）；LRT χ² = 0.260，$p=.610$；AIC 更支持线性模型（20570.74 vs. 20572.48，ΔAIC = −1.74）。H3 未获支持。一种合理解释是观测范围的限制——绝大多数任务的验证密度极低，密度尚未进入边际递减区间；因此在实践上，“多写验证信息”至少在 AgentNet 所覆盖的密度范围内没有可检出的代价。

![图 3　验证密度对任务完成概率的预测效应](paper01_figures/fig3_验证密度与完成概率.png)

#### 4.6 位置分析：存在性重于位置（H4，探索性）

把 2,491 条可定位指令按字符位置三等分（开头/中间/末尾），完成率分别为 83.88%、82.16% 与 81.47%，差异不显著（χ² = 1.426，$p=.490$，Cramer's V = .024）；Bonferroni 校正后的成对比较同样不显著。H4 未获支持。这一“阴性结果”本身有理论含义：终止判准的效能取决于验证信息**是否存在**，而非其在指令中的位置。

### 5 讨论

#### 5.1 证据链的整合

三条证据链——结果层（完成率 +27.6% odds）、总量层（步数 −7.4%）与过程层（终止阶段冗余/错误更低、异常短轨迹近乎减半）——方向一致，共同支持“终止判准”框架的核心预测：显式验证信息帮助智能体把语言目标转译为停止条件，其收益同时体现为更高的达成率与更低的执行浪费。过程层证据尤其重要：如果完成标准只是与“任务更容易”相关，我们不应观察到**条件于难度与长度之后**、且集中出现于终止阶段的系统性差异。

但观察性设计的边界必须同样清楚：完成标准的存在可能与任务类型、用户表达能力、模型对特定表述的训练敏感度等未观测因素相关。本文通篇使用“关联/提示/表明”而非“导致/提升”，所有实践建议均以关联证据为限。

#### 5.2 理论含义

**言语行为理论**：完成标准使指令语力从“做什么”扩展到“如何算做完”，验证动词因此是任务边界的显式标记（Austin, 1962; Searle, 1969）。**关联理论**：验证表述把“确认目标状态”预置为子目标，降低状态评估的认知成本；密度无倒 U 的结果提示，在 AgentNet 的低密度观测区间内，验证信息的边际效应尚未进入递减段（Sperber & Wilson, 1995）。**停止规则理论**：完成标准供给内部终止规则，减少对步数、状态停滞等外部启发式的依赖；异常短轨迹率的减半与终止阶段冗余的下降共同指向这一机制（Gigerenzer et al., 1999; Payne et al., 1993）。

#### 5.3 实践启示

**用户侧**：在指令末尾附加一到两句显式验证要求（“最后请确认文件已存在于目标目录”），成本低而潜在收益明确。**设计者侧**：（1）指令解析阶段把验证关键词映射为内部终止条件候选；（2）执行循环中逐步核对终止条件；（3）指令缺失验证信息时，主动向用户求证以建立共同基础（Clark & Brennan, 1991）。由于密度无倒 U，当前证据不支持对“验证信息过多”的担忧。

#### 5.4 局限性

**因果边界**：观察性二次分析无法操纵完成标准，无法排除未观测混淆（任务难度感知、用户能力、模型训练分布）。建立因果需要随机化指令表述的实验。
**标注边界**：规则化标注对 V1 动词敏感，V2/V3 几乎无样本（5 条与 1 条），H2 不具备检验力；依赖句法或 LLM 辅助标注可提升覆盖率与精度。
**异质性边界**：未按应用领域与智能体模型分层，效应可能被异质性稀释或掩盖。
**指标边界**：终止阶段指标依赖 `last_step_redundant`/`last_step_correct` 的原始标注，无法区分“有意义的验证性步骤”与“无目标的试探步骤”；更细的行为编码是改进方向。

### 6 结论

在 22,532 条真实 GUI 交互轨迹上，本研究检验了一个简单而可操作的想法：用户指令中的完成标准与验证条件，是任务型智能体的天然终止判准。证据链一致表明，显式验证信息与更高的完成率、更少的执行步数以及更干净的终止过程相关联；验证信息的价值在于其存在，而非其位置或数量。实践上，用户应显式写出验证要求，智能体应把验证表述编码为内部终止条件。未来工作沿四个方向推进：提升验证类型的标注精度；以随机化建立因果；检验完成标准与约束密度、任务复杂度的交互；把终止判准机制化，构建可解释的智能体终止决策模块。

### 1 引言

#### 1.1 从验证到约束：问题域的延伸

在前一项研究中（见本系列 Paper 01），本文将用户指令中的完成标准/验证条件重新概念化为任务型交互智能体的"终止判准"，并基于 AgentNet 轨迹数据提供了实证证据：含完成标准的指令与更高的任务完成率、更少的执行步数及更优的终止阶段行为相关联。该研究的核心逻辑在于——明确的验证信息为智能体提供了可操作的停止信号，降低了终止不确定性。

然而，用户指令中还存在另一类具有潜在行为约束力的语言成分：约束表达（constraint expressions）。不同于验证信息（告诉智能体"何时算完成"），约束表达告诉智能体"不能做什么""必须做什么"或"只能做什么"——换言之，它通过对可接受动作集合的限定来塑形智能体的行为空间。验证信息界定任务的**终点**，约束信息界定任务的**边界**。二者共同构成用户指令中语用信息的两个核心维度，但约束表达的效应逻辑可能更为复杂：验证信息主要作用于终止阶段，而约束信息贯穿规划、执行与验证全过程，其密度效应可能呈现非线性的剂量—反应关系。

#### 1.2 约束密度的核心问题

近年以 LLM 为核心的任务型交互智能体在网页浏览、桌面办公与跨应用工作流中展现出强大潜力（Wang et al., 2025; Deng et al., 2023; Yuan et al., 2023），用户指令作为人机协作的"语言入口"，其信息结构与精确度直接影响智能体的行为轨迹（Nakano et al., 2021; Deng et al., 2023）。

在指令设计中，约束表达（如"不要……""必须……""只能……""保持……不变"）是一种常见却未被充分理解的语用手段。从直觉上看，约束通过限定可接受动作集合来提升智能体输出的精确性。然而，一个关键问题悬而未决：**约束是否越多越好？** 当约束密度超过某一阈值时，是否会因规划、验证与冲突消解成本的上升而反而降低完成率？换言之，约束密度与任务完成率之间是否存在倒 U 形关系？如果存在，这一关系的拐点是否因任务情境而异？

既有文献多将约束视为二元特征（有/无），或将其纳入更宽泛的"指令明确性"框架中讨论（Sweller, 1988; Payne et al., 1993）。少量研究开始关注约束的语义类型，但对其密度（density）的剂量—反应关系缺乏系统检验。本研究的核心问题是：**用户指令中的约束密度如何调节任务型交互智能体的动作空间？在什么条件下约束发挥边界作用，又在什么条件下转化为认知负荷？**

#### 1.3 研究边界与核心论点

本研究以 AgentNet 公开数据集中的 GUI 轨迹为经验基础（Wang et al., 2025）。AgentNet 记录了智能体在真实桌面与网页应用环境中执行用户指令的完整操作序列，因此本文所讨论的"任务型交互智能体"特指以 GUI 操作为边界、以自然语言指令为输入的通用型数字智能体。

需要明确的是，AgentNet 数据属于观测性轨迹数据：研究者只能观察到用户"写下了什么指令"以及智能体"最终是否完成"，无法观测用户撰写指令时的真实意图与先验知识。因此，本文所有结论均应在"关联性"而非"因果性"的框架下解读。

本研究的核心论点是：约束在任务型交互智能体用户指令中具有**双重角色**。一方面，适度约束能够减少目标歧义、压缩搜索空间、降低规划分支数，从而提升完成概率；另一方面，当约束密度过高时，智能体需要额外的计算与推理资源来检查约束一致性、处理约束冲突、在局部可行解之间进行权衡，这会增加认知与计算负荷，最终可能抵消边界带来的收益。因此，约束密度与任务完成率之间的关系更可能呈现一种**条件性非线性模式**，而非普适的线性或全局倒 U 形规律。具体而言：

- **低密度**：约束不足，动作空间过大，目标边界模糊，智能体易产生冗余探索；
- **中密度**：约束提供清晰边界，歧义降低，完成率提升；
- **高密度**：约束数量超过智能体的规划与验证容量，冲突风险上升，完成率下降。

更为关键的是，这一非线性关系的拐点与曲率取决于任务情境。高难度任务、长指令任务以及包含多个子任务的任务，其信息需求更高、规划深度更大，因而更容易因约束过载而受损。

### 2 理论基础与研究假设

本研究的理论框架由两条相互交织的线索构成：语用学理论解释约束表达为何具有信息价值，认知负荷理论解释该价值为何存在边界。两条线索共同指向一个核心推论：约束密度是条件性资源，其最优值随任务情境而变化。

#### 2.1 语用学视角：合作原则与关联理论中的约束

从语用学角度看，用户指令本质上是一种以行动达成为目的的指令式言语行为（directive speech act）（Austin, 1962; Searle, 1969）。Grice（1975）的合作原则（Cooperative Principle）指出，成功交际需遵循量的准则（信息量适中）、质的准则（真实可信）、关系准则（内容相关）与方式准则（表达清晰）。在 GUI 指令中，约束表达是方式准则与量的准则共同作用的产物：它通过明确"不能做什么""必须做什么"来降低歧义，但过量的约束又可能违反量的准则，造成信息冗余。

Sperber 与 Wilson（1995）的关联理论（Relevance Theory）进一步为理解约束密度的边界提供了精细的分析工具。该理论强调，语境效果的获取需要付出认知加工成本；听话者（或信息处理系统）会在认知投入与语境收益之间进行权衡。将这一框架迁移到人机场景可推知：智能体在解码指令时，需将每条约束纳入规划与验证；当约束密度超过一定阈值，新增的语境收益可能无法抵消递增的认知与计算成本。Yeung（2016）在工作指令与培训研究中提出的"过犹不及"假说（too-much-of-a-good-thing）也为这一非线性预期提供了来自组织行为学的独立支持。

值得与 Paper 01 进行理论层面的对比：验证信息（完成标准）主要贡献于终止效率，其"过犹不及"风险相对较低——Paper 01 中验证密度未呈现倒 U 形即为佐证。约束信息则不同：它不仅影响终止判断，更影响全局动作选择空间，因此其"过犹不及"风险更为突出——这正是本研究关注约束密度非线性效应的理论动因。

#### 2.2 认知负荷与边界条件框架

认知负荷理论（Cognitive Load Theory）为理解约束密度的条件效应提供了第二视角。Sweller（1988）指出，人类工作记忆容量有限，当外部信息结构超出加工容量时，学习或问题解决绩效会下降。类比到智能体系统，尽管 LLM 在推理阶段并不受限于人类工作记忆，但其规划与验证模块仍受上下文长度、注意力分配与冲突消解能力的约束。高密度约束可能通过以下机制增加系统层面的"负荷"：

1. **规划负荷**：每条约束都需被纳入动作序列生成，约束越多，可行动作组合越复杂；
2. **验证负荷**：执行过程中需反复确认当前动作是否违反任一约束；
3. **冲突消解负荷**：当多条约束相互冲突时，智能体需进行优先级排序或折中推理；
4. **信息检索负荷**：长指令中的高密度约束会稀释关键目标信息，增加语义解析难度。

基于上述理论，本研究将约束密度的效应置于**边界条件**（boundary conditions）框架下：不存在放之四海而皆准的最优密度，效应方向与强度取决于任务需要多少边界、智能体能承受多少验证负荷。这一框架的核心方法论含义是：寻找全局最优密度可能是一个错误的问题；正确的问题应是——在何种条件下，约束密度呈现倒 U 形效应？

#### 2.3 研究假设

综合上述理论，本研究提出以下假设：

**H1（全局效应弱化）**：在混合所有任务的完整样本中，约束密度与任务完成率之间不存在显著的全局倒 U 形关系。该假设的提出基于数据分布的现实：AgentNet 中约 93% 的任务不含任何约束关键词，约束密度呈高度零膨胀分布，全局模型会被大量零值稀释，难以检测到统一的曲率。H1 并非否定约束的价值，而是否定"存在一个适用于所有任务的统一最优密度"这一过于简化的命题。

**H2（条件倒 U 形）**：在任务难度较高、指令长度较长或包含多个子任务的任务子样本中，约束密度与完成率呈显著倒 U 形关系。此时期约束的边界收益与验证成本之间的权衡最为明显——这正是本研究理论框架的核心预测。

**H3（子类型异质性，探索性）**：不同约束子类型（禁止型、保留型、要求型、限制型）的最优密度可能存在差异。例如，禁止型约束可能因直接排除动作而具有较低的过载阈值。该假设为探索性，因各子类型样本量较小、类型重叠度高。

**H4（任务难度调节曲率）**：任务难度显著调节约束密度的二次效应，即二次项与任务难度的交互项为负且显著。难度越高，约束密度的倒 U 形曲率越强——这一假设是对 H2 的精细化，旨在检验调节效应是否具体作用于曲率而非线性斜率。

### 3 研究方法

#### 3.1 数据来源与样本构成

本研究使用 AgentNet 公开数据集的预处理版本（Wang et al., 2025）。原始样本包含 22,532 条 GUI 任务轨迹（已按官方元数据剔除 93 条重复 task_id）。经完整案例分析（listwise deletion）后，主模型纳入 20,205 条任务。其中，指令文本中包含至少一个约束关键词的原始任务为 1,441 条（占 6.40%），进入回归模型的约束任务为 1,237 条。因变量为二值变量 `task_completed`（1 = 完成，0 = 未完成），由轨迹层面的执行结果决定。

本研究的样本构成具有一个不可忽视的结构特征——约束密度的高度零膨胀分布（约 93% 的任务零约束）——这意味着整体样本中约束密度的变异主要由"有/无约束"的二元差异驱动，而非由密度的连续变化驱动。这一特征直接决定了分析策略的选择：必须将"约束有无效应"与"约束密度效应"分开建模。

#### 3.2 约束词分类与密度操作化

参考语用学中情态、言外之力与限定表达研究，本研究将约束表达划分为五类（见表 1）：禁止型（C1）、保留型（C2）、要求型（C3）、限制型（C4）以及混合型（C5，同时包含两类及以上约束）。关键词匹配采用 Python 正则表达式，按不区分大小写、词边界方式匹配；短语优先于单词计数以避免重复。

约束密度（`constraint_density`）定义为约束词绝对频次除以指令词数再乘以 100，以百分比表示；约束丰富度（`constraint_richness`）定义为同时出现的不同约束类型数（0–4）。

**表 1　约束表达的类型学定义与关键词**

| 类型 | 定义 | 关键词 |
|------|------|--------|
| C1 禁止型 | 禁止某些操作或行为 | don't, do not, never, avoid, without, cannot, should not, must not |
| C2 保留型 | 要求保持/保留某状态 | keep, maintain, stay, preserve, leave |
| C3 要求型 | 要求必须完成某事 | must, should, need to, have to, required |
| C4 限制型 | 限定范围、对象或方式 | only, just, merely, exclusively |
| C5 混合型 | 同时包含两类及以上约束 | — |

#### 3.3 三阶段分析框架

为系统回答"约束何时成为负荷"，本研究采用逐层递进的三阶段分析框架。

**Stage 1：约束有无效应。** 在全样本（$N=20{,}205$）中估计 Logistic 模型：

$$
\text{logit}(P(\text{完成})) = \beta_0 + \beta_1 \cdot \text{has\_constraint\_words} + \gamma \cdot \text{task\_difficulty} + \delta \cdot \text{word\_count} + \eta \cdot \text{os}
$$

该阶段回答一个基础性问题：约束表达的"存在"本身是否具有预测价值？结果以比值比（OR）及 95% Wald 置信区间报告。

**Stage 2：约束任务内的全局密度效应。** 将样本限制为包含至少一个约束词的任务（$N=1{,}237$），估计二次 Logit 模型：

$$
\text{logit}(P(\text{完成})) = \beta_0 + \beta_1 \cdot \text{density} + \beta_2 \cdot \text{density}^2 + \gamma \cdot \text{task\_difficulty} + \delta \cdot \text{word\_count} + \eta \cdot \text{os}
$$

若 $\beta_2<0$ 且显著，则支持全局倒 U 形假说。拐点由 $-\beta_1/(2\beta_2)$ 计算，使用 Delta 法估计 95% CI。

**Stage 3：条件模型。** 通过交互项与分样本模型考察任务难度、指令长度、子任务数量等情境变量的调节作用。交互模型形式为：

$$
\text{logit}(P(\text{完成})) = \beta_0 + \beta_1 d + \beta_2 d^2 + \beta_3 M + \beta_4 dM + \beta_5 d^2 M + \text{controls}
$$

其中 $d$ 为约束密度，$M$ 为调节变量。分样本模型按调节变量的中位数或二分取值分别估计二次 Logit。这一阶段的理论目标是：识别约束密度效应的边界条件，即确定"约束何时成为负荷"的具体情境。

#### 3.4 辅助检验与数据特征说明

本研究采用 Dawson（2014）U 形检验判断观测区间两端斜率是否符合倒 U 形预期，使用 Cohen's $f^2$ 评估二次项的解释增量，并以绝对频次、丰富度、限制性立方样条（RCS）及操作系统分样本进行稳健性检验。模型比较以 AIC/BIC 与 McFadden 伪 $R^2$ 为准则。

关于测量有效性，需说明以下几点。其一，约束识别基于关键词规则，具有可解释性与可重复性，但无法识别隐含约束或复杂否定。其二，同一关键词在不同语境中可能承载不同语用功能（例如 "just" 既可是限制词，也可是语气副词），规则匹配会产生一定误判。其三，约束密度以词数为分母，极短指令中单一约束可能产生极端密度值（如 20%），好在高密度观测的稀缺性（95% 分位数仅为 1.75%）使极端值对整体推断的影响有限。尽管存在上述局限，规则检测在现有大规模标注数据稀缺的条件下仍是一种可行且透明的操作化方法。

#### 4.2 Stage 1：约束有无效应

表 4 上半部分报告了 Stage 1 模型结果。在控制任务难度、指令长度与操作系统后，`has_constraint_words` 的回归系数为 −0.054，对应 OR = 0.947（95% CI [0.820, 1.094]，$p=0.459$）。这一结果表明，在完整样本中，未观察到约束有无与任务完成率的显著关联：去重并修正合并膨胀后，早期分析中的显著正相关（OR ≈ 1.165）不再成立，约束的整体价值需在密度与情境维度上考察（见 Stage 3）。

这是一个有信息量的零结果：约束的"存在"本身不携带完成率信息——约束的价值既不在"有没有"，也不在全局平均意义上，而应到密度与任务情境的组合中去寻找。这正是 Stage 2 与 Stage 3 依次检验的问题。

#### 4.3 Stage 2：约束任务内的全局密度效应

将样本限制为包含至少一个约束词的任务（$N=1{,}237$）后，估计二次 Logit 模型。表 4 下半部分报告了结果：约束密度的线性项显著为负（$b=-0.265$，$p=0.037$），但二次项为正且未达传统显著性水平（$b_2=0.016$，$p=0.086$）。按已报告系数推算，拐点位于约 8.4%（$-b_1/2b_2$）；但该记录未包含其 Delta 法置信区间，且二次项本身未达显著（$p=0.086$），因此任何拐点位置都缺乏统计支撑，Dawson 型两端斜率检验的前提亦不成立。结论是：在约束任务整体上，密度效应的曲率证据不足，H1 的“全局效应弱化”预期成立。

#### 4.4 Stage 3：条件模型——任务难度、指令长度与子任务数量

##### 4.4.1 任务难度的调节作用

表 5 报告了交互效应模型与分样本二次模型结果。在交互模型中，约束密度二次项与任务难度的交互项显著为负（$b=-0.0085$，$p=0.027$），而密度线性项与难度的交互项不显著（$b=0.032$，$p=0.240$）。这意味着任务难度调节的是约束密度的**曲率**而非其线性斜率——随着难度增加，密度—完成率关系从近乎平坦逐渐弯曲为倒 U 形。

按任务难度中位数（6）分样本后，模式更为清晰：高难度任务子样本（$N=8{,}169$）的二次项显著为负（$b_2=-0.037$，$p=0.029$），拐点约 1.85%（95% CI [0.86, 2.83]）；低难度任务子样本（$N=12{,}036$）的二次项不显著（$b_2=0.007$，$p=0.206$）。该结果支持 H2 与 H4，为本研究的核心理论预测——约束密度效应取决于任务情境——提供了关键的实证证据。

##### 4.4.2 指令长度的调节作用

按词数中位数（30）分样本后，长指令任务子样本（$N=10{,}028$）呈现显著倒 U 形（$b_2=-0.039$，$p=0.034$），拐点约 1.60%（95% CI [0.69, 2.50]）；短指令任务子样本（$N=10{,}177$）的二次项不显著（$b_2=0.008$，$p=0.207$）。长指令与高密度约束叠加时，信息稀释与验证负荷效应更加明显——这与关联理论的预期一致：在信息总量已经较大的情况下，新增约束的边际语境收益递减，而加工成本递增。

##### 4.4.3 子任务数量的探索性条件效应

除任务难度与指令长度外，本研究进一步考察了 `has_multiple_subtasks` 的调节作用。在包含多个子任务的任务子样本（$N=12{,}902$）中，约束密度呈现显著倒 U 形（$b_2=-0.043$，$p=0.009$），拐点约 1.82%（95% CI [1.13, 2.50]）；单个子任务子样本（$N=7{,}303$）中二次项不显著（$b_2=0.010$，$p=0.147$）。这一发现与任务难度、长指令结果形成高度一致的三角验证：三种操作化方式均指向同一结论——任务结构越复杂，约束密度的倒 U 形效应越显著。

### 5 讨论

#### 5.1 从"全局定律"到"边界条件"：理论贡献的重新定位

本研究最重要的理论贡献在于将"约束密度是否最优"这一问题从"寻找普适定律"转向"识别边界条件"。整体样本与约束任务子样本均未发现显著的全局倒 U 形效应，这与"过犹不及"假说（Yeung, 2016）的直接推论不一致——如果约束只是单纯地"越多越糟"，那么全局二次项应当显著为负。然而，调节效应分析揭示了一个关键边界：只有在高难度任务、长指令任务或多子任务任务中，约束密度才表现出显著倒 U 形。

这一发现将本研究与 Paper 01 的发现置于互补的理论位置。Paper 01 表明，验证信息（完成标准）与执行效率呈正向关联，且验证密度未呈现倒 U 形——因为验证信息主要作用于终止阶段，认知成本相对有限。Paper 02 则表明，约束信息的效应更加微妙：其价值高度依赖于任务情境；在简单任务中，约束增减的影响微乎其微；在复杂任务中，约束密度存在一个狭窄的"甜蜜点"（约 1.7%–1.9%）。两条线索共同指向一个更一般的理论命题：**用户指令中不同语用成分的效能边界取决于该成分所触发的认知加工类型与加工负荷。**

#### 5.2 低、中、高约束密度的作用机制

综合本研究的各项发现，可对约束密度的作用机制进行如下分层描述：

- **低密度（< 1%）**：约束提供的信息边界不足，智能体需要在较大动作空间中搜索，容易产生偏离目标的探索。Stage 1 的零结果提示，“有/无约束”的二元区分本身不携带完成率信息——边界缺失的代价要到密度与任务情境的组合中才显现（Stage 3）。
- **中密度（约 1.7%–1.9%）**：对于复杂任务，该区间是约束收益最大化的"甜蜜点"。此时约束数量足够压缩动作空间、澄清目标，但又未多到引发严重冲突与验证负荷。值得注意的是，高难度、长指令与多子任务任务的拐点均落在 1.7%–1.9% 附近——这一跨操作化的一致性为该区间的实际参考价值提供了交叉验证。
- **高密度（> 2%–3%）**：约束数量超出智能体的有效处理能力。规划模块需在大量约束下搜索可行路径，验证模块需反复检查每一步是否违规，冲突消解模块需处理相互矛盾的约束——各项成本叠加，最终表现为完成率下降。

#### 5.3 与认知负荷理论和关联理论的对话

从认知负荷视角看（Sweller, 1988），简单任务本身信息需求较低，额外约束带来的收益有限但成本亦低，因此密度效应不显著；复杂任务需要更多指引，但过量约束可能迅速超出智能体的规划容量，与性能下降相伴随（Sweller, 1988; Payne et al., 1993）。

关联理论（Sperber & Wilson, 1995）则进一步解释为何长指令任务对高密度约束更敏感：在信息总量已经较大的情况下，新增约束的边际语境收益递减，而加工成本递增。这一"边际收益递减"逻辑与经济学中的"最优边界"概念形成了有趣的理论共鸣。

#### 5.4 三阶段框架的方法论意义

本研究采用的三阶段分析框架——约束有无效应 → 全局密度效应 → 条件效应——为研究大规模观测轨迹数据中的非线性效应提供了一种可推广的方法论模板。该框架的核心设计原则是：先确认基础效应的存在，再检验高阶效应的普遍性，最后通过情境变量识别边界条件。这一递进逻辑有效避免了直接将全局非线性模型应用于零膨胀数据所导致的效应稀释与错误推断。

#### 5.5 实践建议

基于研究发现，对任务型交互智能体的提示工程提出以下建议：

1. **高难度任务**：将约束密度控制在 1.7%–1.9% 左右。避免在已复杂的任务中堆砌过多否定词、限定词或强制词。
2. **长指令任务**：鉴于信息稀释效应，长指令中的约束应更精练，优先保留与核心目标直接相关的约束。
3. **多子任务任务**：每个子任务可单独给出关键约束，但全局层面的约束密度仍应控制在 1.7%–1.9% 附近。
4. **简单任务**：约束密度的容忍区间较宽，但仍需避免极端高密度（如 > 5%）。
5. **接口设计**：可在用户输入指令后提供约束密度反馈，对高密度提示给出精简建议，尤其针对高难度或长任务。

#### 5.6 局限与未来方向

本研究存在以下局限。第一，约束检测的规则性——基于关键词的方法无法识别隐含约束与语义强度差异，可能引入测量误差。第二，观测性设计——无法排除任务领域、应用类型、用户能力等未观测混淆；所有效应均为关联性。第三，高密度观测稀缺——95% 分位数仅为 1.75%，限制了对高密度区间曲率的统计功效。第四，本文的倒 U 形证据来自分样本二次模型而非全局模型，拐点区间由 Delta 法近似得到，在零膨胀稀疏数据上应作为参考区间而非精确最优值。

未来研究可从以下方向拓展：（1）使用大语言模型进行更精细的约束语义抽取与人工校验；（2）开展控制实验，随机分配不同约束密度以验证因果关系；（3）构建中介模型，检验冗余步数、验证步数是否在密度与完成率之间发挥中介作用；（4）在多模态智能体与机器人任务中验证结论的跨领域适用性；（5）与本系列 Paper 03 中的语用结构类型学进行交叉分析，探讨约束密度如何与整体语用结构类型交互影响执行效果。

### 6 结论与展望

本研究基于 AgentNet 大规模 GUI 轨迹数据，系统考察了用户指令中约束密度对任务完成率的非线性影响。主要结论如下：

1. 在完整样本中，约束有无与任务完成率无显著关联（OR ≈ 0.947）；约束表达的价值不体现在"有无"层面，而体现在密度与任务情境的交互中。
2. 在约束任务子样本中，不存在稳健的全局倒 U 形密度效应；约束密度的二次项不显著。
3. 任务难度、指令长度与子任务数量显著调节约束密度的效应：在高难度、长指令或多子任务情境下，约束密度呈现显著倒 U 形，最优密度集中在 1.7%–1.9% 附近。
4. 冗余步数比在中等密度时达到峰值，暗示约束密度可能通过探索—验证权衡影响执行效率。

本研究的理论意义在于将"约束密度最优"问题重新界定为"约束何时成为负荷"的边界条件问题——这一重新框架化将问题从对"普适最优值"的无效寻找中解放出来，转向对"情境条件"的精准识别。实践意义在于为提示工程提供了可量化的密度参考区间。未来研究可在更大规模、更高质量标注数据的基础上，进一步探索约束的语义角色、因果机制与跨任务泛化能力，并将本研究的发现与语用结构类型学（Paper 03）进行整合分析。

### 1 引言

#### 1.1 从"成分"到"结构"：分析单元的提升

本系列的前两项研究分别考察了用户指令中两类关键语用成分的独立效应：Paper 01 将完成标准/验证条件重新定位为任务型交互智能体的"终止判准"，提供了其与执行效率正向关联的经验证据；Paper 02 将约束密度界定为"条件性边界资源"，揭示了其与任务完成率之间的非线性关系如何随任务情境而变化。两项研究在各自的分析层面提供了有价值的发现，但均聚焦于**单一语用成分**——验证信息或约束信息——与执行效果之间的关联。

然而，真实的用户指令并非由孤立语用成分拼凑而成。一条指令可能同时包含操作对象描述、动作顺序说明、文件路径引用、约束条件与完成标准，也可能仅由一个简短的动作短语构成。用户如何将这些信息维度**组合**为一个整体的语用结构——而非各维度的简单加总——才是理解指令质量的关键。换言之，前两项研究回答了"某一成分是否重要"，本研究则回答一个更为根本的问题：**用户如何通过自然语言将任务组织为可执行的语用结构？这些结构类型在执行效果上是否存在系统性差异？**

#### 1.2 指令质量的"组合性"问题

任务型交互智能体以自然语言指令为"语言入口"，其典型执行链路可概括为：用户任务表达 → 任务表征 → 动作规划 → 环境操作 → 反馈修正 → 结果验证 → 执行终止。在这一链路中，指令不仅是语义输入的载体，更是智能体构建任务表征、设定动作边界与判断完成状态的语用框架（Nakano et al., 2021; Deng et al., 2023）。

现有研究多从任务完成率、步骤长度、错误率等结果指标评估智能体性能，对输入端指令的语用结构关注不足（Wang et al., 2025; Deng et al., 2023）。提示工程的实践表明，指令的明确性、约束性与结构性影响模型对用户意图的解析精度（Deng et al., 2023; Nakano et al., 2021）。然而，一个关键的方法论问题尚未被充分探讨：指令质量的"组合性"——即不同语用维度的**组织方式**本身是否构成一个独立于各维度简单加总的信息源？

这一问题具有直接的方法论含义。若语用维度的组合方式确实与执行效果存在独立关联，那么仅用显式性评分（将各维度相加）或单一维度（如约束密度）来评估指令质量，在方法论上就是不充分的。这也正是 Paper 01 与 Paper 02 各自所不能回答的问题：验证密度与约束密度是否只是同一潜在语用结构的两个表层指标？不同类型用户指令的语用结构是否存在可识别的"类型"，而非连续谱系上的任意一点？

#### 1.3 研究问题与定位

本研究以 AgentNet GUI 交互轨迹为经验基础（Wang et al., 2025），借鉴语用类型学、言语行为分类学（Austin, 1962; Searle, 1976）与共同基础理论（Clark & Brennan, 1991），构建包含 11 个二元语用特征的分析框架，并采用潜类别分析（LCA）识别用户指令的潜在语用结构类型。本研究的核心问题有三个递进层次：

1. **存在性问题**：AgentNet 用户指令是否存在可识别的潜在语用结构类型？
2. **差异性问量**：不同语用结构类型在执行效果（完成率、过程指标、路径稳定性）上是否存在系统性差异？
3. **独立性问题**：语用结构类型的效应是否独立于线性显式性评分？是否受任务难度调节？

研究方法论上的定位是：将分析单元从 Paper 01/02 的"单一语用成分"提升至"整体语用结构"，从而为指令质量的组合性评估提供经验基础。

### 2 理论基础与研究假设

本研究的理论框架由三条线索交织而成：语用类型学与言语行为分类学界定"有哪些语用维度"；共同基础理论解释"为什么语用结构差异会影响执行"；潜类别分析提供"如何识别类型"的方法论基础。

#### 2.1 语用类型学与言语行为分类学

语用类型学关注语言使用者在特定交际场景中对语言形式的选择及其功能后果。Austin（1962）的言语行为理论将语言视为行为，区分言内行为（locutionary act）、言外行为（illocutionary act）与言后行为（perlocutionary act）。Searle（1976）进一步将言外行为划分为断言类、指令类、承诺类、表达类与宣告类五类。在任务型交互智能体场景中，用户指令主要属于指令类言语行为——其核心语力（illocutionary force）在于促使智能体执行特定操作。

然而，指令类言语行为内部存在丰富的结构性变异。有些指令强调动作本身（"点击按钮""输入文字"），有些强调操作对象（"打开那个文件""修改第三张表格"），有些强调约束条件（"只能使用终端""不要修改原文件"），还有些强调完成标准（"确认重命名成功""检查是否在打折"）。这些差异并非程度上的"多一点或少一点"，而是**组织方式**上的质的不同——它们反映了用户如何将任务映射为语言表达的不同语用策略。

本研究从指令文本中提取的 11 个二元语用特征（是否明确应用、操作对象、目标动作、目标状态、文件引用、对象属性、操作顺序、多子任务、约束词、完成标准、初始状态）覆盖了"谁/什么/怎么做/做到什么程度"四个语用维度，构成一个系统性的语用特征空间。不同于 Paper 01 与 Paper 02 各自关注单一维度（验证信息或约束信息），本研究将这些维度视为一个整体的特征空间，考察其潜在结构。

#### 2.2 共同基础理论与指令理解

共同基础理论（Clark & Marshall, 1981; Clark, 1996; Clark & Brennan, 1991）指出，成功交际依赖于交际双方共享的背景知识与情境信息。在人机交互中，智能体需要基于用户指令推断当前状态、目标状态以及达到目标所需的操作序列。若指令中明确包含操作对象、操作顺序、初始状态与完成标准，则共同基础更为充分，智能体在规划与验证阶段的不确定性更低。

将这一理论框架与本系列前两项研究对接，可形成以下推论。Paper 01 表明，验证信息为智能体提供了终止判断的基础；Paper 02 表明，约束信息在适度时压缩了动作空间，过度时增加了负荷。共同基础理论则将这些发现整合进一个更为一般的框架：**指令语用结构的根本功能是为智能体建立"共享任务情境"**。验证信息界定"终点"，约束信息界定"边界"，对象信息界定"实体"，动作信息界定"路径"——各类语用信息的组合方式决定了共同基础的充分程度，进而影响执行路径的稳定性。

#### 2.3 研究假设

基于上述理论，本研究提出以下假设：

**H1（语用类型的存在性）**：AgentNet GUI-Agent 用户指令存在可识别的潜在语用结构类型，可通过 LCA 从 11 个二元语用特征中识别出来。本假设为 LCA 的基本前提——若数据中不存在潜在类别结构，模型选择指标将不支持 $k>1$ 的解。

**H2（完成率差异）**：不同语用结构类型的任务完成率存在显著差异。若 H2 成立，则说明语用结构的组织方式与任务最终结果存在关联。

**H3（过程稳定性差异）**：不同语用结构类型在总步数、错误比例、冗余比例以及路径稳定性指标（最长连续错误步数、转换次数、转换率）上存在显著差异。H3 是本研究的核心假设——它关注的是"如何执行"而非"是否完成"，更直接地检验语用结构对执行过程的影响。

**H4（独立于显式性评分）**：在控制显式性评分（11 个特征之和）后，语用结构类型仍与完成率存在独立关联。若 H4 成立，则说明语用结构的组合方式提供的预测信息无法被简单的特征计数所替代——这是对"组合性"问题的直接检验。

**H5（任务难度调节效应）**：语用结构类型与任务难度对完成率的关联存在交互效应。基于 Paper 02 的发现——约束密度的效应随任务难度而变化——可预期，包含更多约束信息的语用类型在不同难度下的表现可能存在不对称性。

### 3 研究方法

#### 3.1 数据来源与样本

本研究使用 AgentNet 公开 GUI 交互轨迹数据集（Wang et al., 2025）。原始数据包含 22,532 条任务尝试记录（已按官方元数据剔除 93 条重复 task_id）。经对关键结果变量（`task_completed`、`total_steps`、`incorrect_steps`、`redundant_ratio`）进行完整案例分析后，最终纳入分析的记录为 20,205 条。分析单元为单次任务尝试；需注意，同一 `task_id` 可能存在多次尝试，步级路径指标按 `task_id` 聚合后映射到所有尝试——因此路径分析中有效样本量的解释需审慎。

本研究属于对公开数据的二次分析，未重新运行智能体，亦未收集新的交互日志。

#### 3.2 语用特征提取

依据语用类型学与言语行为分类学，本研究从指令文本中提取 11 个二元语用特征，覆盖"谁/什么/怎么做/做到什么程度"四个语用维度（见表 1）。

**表 1　11 个二元语用特征的定义与语用维度**

| 语用维度 | 特征 | 定义 |
|----------|------|------|
| 谁/什么 | `has_application` | 是否明确指出应用或软件 |
| 什么 | `has_operation_object` | 是否明确指出操作对象 |
| 什么 | `has_file_reference` | 是否提供文件名、路径、工作表名或页面名 |
| 什么 | `has_object_properties` | 是否给出对象属性（颜色、位置、格式、数量等） |
| 什么 | `has_initial_state` | 是否说明当前初始状态 |
| 怎么做 | `has_target_action` | 是否明确指出目标动作 |
| 怎么做 | `has_operation_order` | 是否说明操作顺序 |
| 怎么做 | `has_multiple_subtasks` | 是否包含多个可区分的子任务 |
| 怎么做 | `has_constraint_words` | 是否包含约束词（only / don't / keep / avoid 等） |
| 做到什么程度 | `has_completion_criteria` | 是否给出完成或验收标准 |
| 做到什么程度 | `has_target_state` | 是否明确指出目标状态 |

特征提取采用基于关键词与正则表达式的规则方法。显式性评分（`explicitness_score`）定义为上述 11 个正向特征之和。

关于测量有效性，需说明以下几点。第一，上述特征由规则自动提取，未经人工标注的精度、召回率、F1 或 Cohen's κ 检验——特征命中与否反映的是文本中是否出现对应语言线索，而非对语用功能的完美刻画。第二，部分关键词在不同语境下可能承载不同功能（例如 "check" 既可表示验证标准，也可表示动作本身），规则方法会产生一定误分类。第三，尽管存在上述局限，规则型特征抽取在现有大规模标注数据稀缺的条件下，仍是一种可行且透明的操作化方法。

#### 3.3 潜类别分析（LCA）实现

本研究采用潜类别分析（LCA）识别用户指令的潜在语用结构类型。LCA 的核心思想是：观测变量之间的关联可由一个潜在的类别变量解释；在给定潜在类别后，各观测变量条件独立（Lazarsfeld & Henry, 1968）。

由于 R 语言 `poLCA` 包在当前环境中不可用，本研究使用 Python 实现了标准的二元潜类别 EM 算法（Goodman & Frank, 2016 的概率推理框架）。对每个 $k=1$ 至 8，分别进行多次随机初始化的 EM 拟合，并保留对数似然最大的解。模型选择综合考察 AIC、BIC、熵（entropy）与 BIC 相对改善率截止准则（改善率低于 0.15% 时截止）。作为探索性对比，同时拟合了 sklearn 的 GaussianMixture（tied covariance），其在 $k=5$ 时与 EM-LCA 的 Adjusted Rand Index 为 0.372，提示专用二元 LCA 更适合当前数据类型。

EM 算法的实现步骤如下：（1）对每个 $k$，进行多次随机初始化（每次随机分配类别成员概率并归一化）；（2）E 步：基于当前参数估计，计算每条观测属于各类别的后验概率；（3）M 步：基于后验概率加权更新各类别的条件响应概率与类别先验概率；（4）迭代至对数似然收敛（变化量 $< 10^{-6}$）。

#### 3.4 过程结果与路径指标

过程结果指标包括：`total_steps`（总步数）、`incorrect_ratio`（错误步数占比）、`redundant_ratio`（冗余步数占比）。路径稳定性指标从步级数据中提取并按 `task_id` 聚合，包括：`first_error_position`（首次错误位置相对总步数）、`max_consecutive_incorrect`（最长连续错误步数）、`transition_count`（相邻正确/错误状态转换次数）与 `transition_rate`（转换次数占有效相邻对的比例）。

路径稳定性指标的设计遵循以下逻辑：`max_consecutive_incorrect` 捕捉智能体偏离正轨的最大持续性；`transition_count` 与 `transition_rate` 捕捉正确—错误状态之间的振荡频率——一条稳健的执行轨迹应表现为"少量偏离、快速纠正"，而非"反复错—改—错"的振荡模式。

#### 3.5 分析流程

步骤 1：特征提取与描述性统计；
步骤 2：对 $k=1$ 至 8 拟合 EM-LCA，依据 BIC 肘部法则与熵选择最优 $k$；
步骤 3：基于条件响应概率为每个潜在类别赋予语用标签；
步骤 4：使用卡方检验比较各类别完成率，使用 ANOVA/MANOVA 比较过程性结果；
步骤 5：构建控制显式性评分的逻辑回归模型，检验语用类别的独立预测效应；
步骤 6：引入任务难度与语用类别的交互项，检验调节效应；
步骤 7：对执行路径指标进行类别间比较；
步骤 8：通过训练—测试划分与 Bootstrap 进行模型稳定性检查。

### 5 讨论

#### 5.1 五种语用结构类型的执行意义

通过 LCA 识别的五种语用结构类型，可理解为用户在 GUI 任务场景中组织任务信息的五种语用策略。不同于将指令特征视为连续谱系上的任意点，类型学视角揭示了指令语用结构的"离散性"——用户倾向于以特定的特征组合方式来组织指令，而非在所有维度上等概率地"多写一点"。

对象/文件丰富型通过明确的实体锚定降低了实体解析阶段的不确定性。其总步数最长（$M=22.37$），可能反映该类任务本身的复杂度较高（涉及文件操作、对象属性修改等）；但同时，其错误比例与冗余比例处于中等水平——信息丰富并不必然带来高错误率，暗示充分的语用信息可能在更复杂的任务中发挥了"导航"功能。

极简型是第二常用类型（30.83%），但其过程指标表现最差——错误比例（0.141）与冗余比例（0.093）均为五类最高。这一发现挑战了"指令越短越好"的朴素直觉：极简型指令虽然节省了用户的输入成本，但将信息补全的认知成本转移给了智能体。在缺少明确操作对象、动作顺序与验证标准的情况下，智能体需要通过试探—纠错来逼近目标，表现为较高的冗余步比例与路径转换率。

动作约束型在过程稳定性上的一致优势（三项路径指标均为最低）是本研究最值得关注的发现。该类指令同时具备明确的目标动作（0.949）、完成标准（0.798）与约束词（1.000）——换言之，它同时在"做什么""做到什么程度"与"不能做什么"三个语用维度上为智能体提供了信息。这一"三维完整"的语用结构可能使智能体在规划、执行与验证三个阶段均获得明确指引，从而减少了执行过程中的方向性偏差与振荡。

动作导向型是绝对主导的指令类型（47.75%），但其完成率最低、转换次数最高。这一模式提示，"动作描述丰富"并不等同于"语用结构完整"——如果大量的动作描述缺乏约束边界与验证终点的配合，智能体可能在执行过程中更容易产生路径波动。

约束验证型样本量最小（4.16%）但完成率最高（83.2%）。该类指令通常对应"检查""确认""设置变更"等目标状态较易判定的任务。然而，受限于样本量与任务类型分布，对其过程优势仍需谨慎解读。

#### 5.2 路径稳定性作为语用结构效应的核心证据

本研究主张，评估指令质量应延伸至执行过程的稳定性，而非止步于完成率。完成率是综合性终局指标，同时受任务难度、智能体能力与环境状态等多种因素影响；相较之下，路径稳定性指标——最长连续错误步数、转换次数与转换率——更为直接地反映了指令语用结构对执行过程的微观影响。

本研究中，动作约束型在完成率上并非最高（82.0%，低于约束验证型的 83.2%），但其路径稳定性最优。这一"完成率与路径稳定性脱耦"现象提示：不同的语用结构可能通过不同的机制影响执行效果——约束验证型的完成率高可能得益于任务本身目标状态易于判定；动作约束型的路径稳定性好则可能源于执行过程中的方向性指引更充分。仅关注"是否完成"会掩盖语用结构在"如何执行"层面的系统性差异。

#### 5.3 与 Paper 01/02 的理论整合

将本研究的发现与前两项研究整合，可构建一个更为完整的理论图景（图 5）。

Paper 01 表明，验证信息（完成标准/验证条件）与执行效率正向关联——验证信息为智能体提供了终止判准。Paper 02 表明，约束信息的效应是条件性的——在高难度或长指令任务中呈现倒 U 形，最优密度约 1.7%–1.9%。Paper 03 则揭示了更高层次的组织原则：用户指令中的不同语用维度不是随机组合的，而是倾向于聚合成若干可识别的"语用结构类型"——在这些类型中，动作导向型（以"怎么做"为主导但缺乏约束与验证）完成率最低，动作约束型（同时包含"怎么做""做到什么程度"与"不能做什么"）路径最稳健。

三者共同指向以下推论：**用户指令对智能体执行的影响，既取决于关键语用成分的剂量（密度），也取决于这些成分的组织方式（结构类型），最终都受任务复杂度的调节。** 这一推论具有直接的实践含义——提示工程不应仅关注"加了什么信息"，还应关注"信息如何组织"。

**图 5** 以概念框架图的形式整合了本系列三项研究的理论关系。自下而上呈现了三个递进的分析层次——层次一（单一语用成分的存在/缺失：Paper 01 验证信息与 Paper 02 Stage 1 约束信息）、层次二（语用成分的剂量效应：Paper 02 约束密度的非线性与条件效应）、层次三（整体语用结构类型：Paper 03 五类别 LCA）。右侧标注了贯穿三个层次的情境调节变量（任务复杂度），底部汇总了系列研究所覆盖的多维度执行效果（完成率、执行步数、路径稳定性、冗余步数比、错误模式）。该图揭示的核心推论是：指令效果 = f（语用成分剂量，语用结构类型，任务复杂度）。

#### 5.4 显式性评分的局限性

控制显式性评分后，语用类别仍与完成率存在独立关联（$\chi^2(4)=21.44$，$p<0.001$），而显式性评分本身不显著（$b=0.018$，$p=0.262$）。这一结果为"组合性"问题提供了经验证据：**不同语用维度的组合方式提供的预测信息，无法被各维度的简单加总所替代。** 举例而言，一条得分为 5 的指令可能对应完全不同的语用结构——可能是"5 个动作描述"（动作导向型），也可能是"对象+动作+顺序+约束+验证"（动作约束型）——两者在执行效果上可能存在系统性差异。

这一发现对提示工程的启示是：优化提示时不宜简单追求"显式性分数"的提高，而应关注语用结构的完整性——确保指令在"谁/什么""怎么做""做到什么程度""不能做什么"四个维度上均有覆盖。

#### 5.5 局限与未来方向

本研究存在以下局限：

1. **规则型特征的有效性**：11 个二元语用特征由关键词与正则表达式规则提取，未经人工标注的精度、召回率、F1 或 Cohen's κ 检验。未来可引入大语言模型辅助标注或进行人工校验，提升特征有效性。

2. **观测数据的因果解释**：语用结构类型与执行效果之间的关联不能解释为因果效应。用户可能根据任务复杂度自选择不同的表达方式，类别—结果关联可能受任务特征混淆。未来可通过实验操纵（如随机分配不同语用结构的指令）或工具变量方法进一步探讨因果路径。

3. **LCA 实现的近似性**：自定义 EM 算法未提供 Lo-Mendell-Rubin 检验与参数 Bootstrap 置信区间；稳定性检查虽初步支持五类别解，但 Bootstrap 次数有限（5 次），publication-grade 推断需更充分的计算验证。

4. **结论的外部效度**：本研究基于 AgentNet 桌面 GUI 轨迹数据，向网页智能体、移动设备、机器人控制等环境的推广需进一步验证。

5. **重复 task_id 与路径指标**：同一 `task_id` 的多次尝试导致路径分析的有效样本量解释需审慎，未来可采用混合效应模型处理任务层级嵌套结构。

### 6 结论与展望

本研究以 AgentNet 大规模 GUI 轨迹数据为基础，从"语用结构类型学"的视角考察了用户指令的语用组织方式及其执行效应。核心发现如下：

1. 任务型交互智能体的用户指令存在五种可识别的潜在语用结构类型：对象/文件丰富型、极简型、动作约束型、动作导向型与约束验证型。
2. 五类在执行路径稳定性、过程性结果与任务完成率上均存在显著差异。动作约束型在执行路径上最为稳健——最长连续错误步数、转换次数与转换率均为最低；极简型的过程效率损失最大。
3. 语用结构类型对完成率的预测关系独立于线性显式性评分，表明特征的组合方式比特征的简单计数包含更丰富的预测信息。
4. 动作约束型在低难度任务中的完成率优势随难度上升而减弱，提示任务复杂度是语用结构效能的关键边界条件。

本研究的理论贡献在于将指令质量评估从"单一成分剂量"（Paper 01/02 的视角）提升至"整体结构类型"的分析层面，并主张以路径稳定性而非仅完成率作为语用结构效应的核心判断指标。实践贡献在于为提示工程提供了基于类型学的诊断框架——不仅看指令"写了多少"，更看指令"如何组织"。

未来研究可从以下方向拓展：第一，将语用结构类型作为先验信息融入智能体的自适应提示补全模块，实现面向语用结构的动态指令优化；第二，在跨语言、跨平台数据中检验该类型学的跨域稳健性；第三，采用实验设计检验语用结构类型与执行效果之间的因果路径；第四，结合本系列 Paper 01（验证密度）与 Paper 02（约束密度）的发现，构建一个整合"成分剂量 × 结构类型 × 任务复杂度"的多层次指令效能预测框架。

# 综合讨论与展望

## 核心发现回顾

本系列三项研究构建了一个递进式的分析框架，分别从"单一语用成分的存在性"、"语用成分的密度/剂量效应"和"整体语用结构类型"三个层次，考察了用户指令语用特征对任务型交互智能体执行效果的影响。

研究一表明，验证信息（完成标准）作为终止判准，提供了智能体判断"何时停止"的关键语言线索。研究二进一步揭示，约束信息的效应并非简单的线性关系，而是取决于任务情境——在高难度和长指令条件下呈现显著倒 U 形。研究三将分析单元提升至语用结构的整体组织方式，发现了五类稳定的指令类型，其中动作约束型在路径稳定性上表现最优。

## 理论贡献

1. **言语行为理论的拓展**：将 Austin 和 Searle 的经典言语行为理论拓展至人机交互领域，揭示了指令内部语用结构的多样性及其行为后果。
2. **关联理论的量化检验**：为 Sperber 和 Wilson 的关联理论在人机交互情境中的应用提供了大规模经验证据。验证信息降低认知成本、约束信息存在"过犹不及"效应——两者从不同侧面支撑了认知经济性原则。
3. **认知负荷理论在智能体系统中的延伸**：证明了即便对于 LLM 驱动的智能体系统，输入端的语用密度仍会通过规划、验证和冲突消解机制影响任务执行效果。
4. **共同基础理论的过程层面实证**：Clark 和 Brennan 的共同基础理论被拓展至智能体执行的过程层面——语用结构的充分性不仅影响"能否完成"，更影响"如何完成"（路径稳定性）。

## 实践启示

1. **指令设计原则**：对高难度、长指令任务，约束密度建议控制在 1.7%–1.9% 左右，避免约束过载。
2. **完成标准的价值**：明确包含验证条件的指令与更高的执行效率相关联，建议在提示工程和指令模板中嵌入明确的完成判据。
3. **语用结构诊断**：五类语用结构类型为用户指令质量评估提供了类型学框架，可用于智能体提示优化的前置诊断。
4. **终止机制设计**：智能体系统应增强对指令中完成标准的识别与利用能力，将终止判断从启发式规则升级为语言驱动的内部终止规则。

## 局限与未来方向

1. **观测性数据局限**：AgentNet 为观测性轨迹数据，所有发现均为统计关联而非因果效应。未来研究可采用实验设计，随机分配约束密度和完成标准条件，实现因果推断。
2. **数据集代表性**：AgentNet 的指令主要来源于英文环境下的桌面/网页 GUI 任务。中文及跨语言、跨操作系统场景的适用性有待验证。
3. **智能体架构差异**：不同智能体系统（如基于视觉的 vs. 基于 DOM 的）可能对同一语用特征产生不同响应，本研究未能区分架构类型的调节效应。
4. **语用特征细粒度**：11 个二元语用特征虽覆盖了主要维度，但未能捕捉语义强度、约束优先级、歧义程度等连续谱系信息。
5. **动态适应**：约束密度的最优值可能随智能体能力演进和任务域迁移而变化，未来需建立自适应约束密度估计框架。
6. **终止机制的因果检验**：本研究提出的"完成标准→终止判准→执行效率"理论链尚需通过实验操控来检验其因果方向。
