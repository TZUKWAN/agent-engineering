# 论文01：用户提示中的验证显性度对GUI智能体执行终止机制的影响

## 研究背景与问题

在22,811条AgentNet任务的前期分析中，`has_completion_criteria`（是否说明完成标准/验证方式）是11个显性度特征中对任务完成率**效应最大的特征**（有该特征的任务完成率82.3% vs 无该特征的78.8%，差异+3.5%）。这暗示"告诉智能体怎么验证结果"可能比"告诉智能体做什么"更重要。

然而，前期分析仅做了简单的"有vs无"二值比较，未深入分析：
1. 验证标准的**语言形式差异**（动词式"check/verify/confirm" → 状态式"done/complete/correct"）是否效果不同
2. 验证标准如何影响**执行终止机制**（是减少不必要的冗余步骤？还是提高首次正确率？）
3. 验证表述的**细化程度**（简单提及 vs 详细说明验证方法）与执行效能的关系

本研究从言语行为理论出发，将"验证显性度"概念化为用户向智能体发出的**验证言语行为**，考察其对智能体执行终止过程的语用调节机制。

## 理论基础

- **言语行为理论**（Austin 1962, Searle 1969）：提示中的验证表述是一种"宣告式"言语行为，规定任务完成的评判标准
- **关联理论**（Sperber & Wilson 1986）：验证标准的明确性降低了智能体对"什么算完成"的推断成本，使智能体更早、更准确地终止执行
- **行动终止理论**（Anderson 2002）：明确的终止条件减少过冲和冗余搜索行为

## 核心假设

| 编号 | 假设 | 预期方向 |
|------|------|---------|
| H1a | 有验证标准的任务，完成率高于无验证标准的任务 | +，已初步验证（+3.5%） |
| H1b | 有验证标准的任务，执行步数显著少于无验证标准的任务 | - |
| H1c | 有验证标准的任务，**冗余步骤比例**显著低于无验证标准的任务 | - |
| H2 | 验证标准的语言形式（动词式"check/verify" vs 状态式"done/complete"）对执行终止的影响程度不同 | 动词式 > 状态式 |
| H3 | 验证表述的细化程度与冗余步骤比例呈倒U形关系（表述太粗略不够用、太细节限制灵活） | 非线性 |

## 实验设计

### 第一步：验证标准的语言分类标注

**目标**：对`has_completion_criteria=1`的2,869条指令，进一步细分验证标准的类型

**标注方案**：

| 类别 | 定义 | 关键词示例 |
|------|------|-----------|
| V1-动词指令式 | 明确说"去检查/确认"某个结果 | check, verify, confirm, validate, ensure, make sure |
| V2-状态目标式 | 描述任务完成后的状态 | done, complete, correct, proper, finished, ready |
| V3-条件验证式 | 说"当XXX时/如果XXX"才算完成 | until, when...then, once, after |
| V4-混合式 | 同时包含以上多种 | |
| V0-不可分类 | 伪阳性（词匹配了但语义上不是验证） | 人工复核后标记 |

**标注方法**：基于关键词+正则的规则标注，对模糊案例用关键词共现矩阵辅助判断。

### 第二步：执行终止机制分析

**分析内容**：

| 分析 | 方法 | 输出 |
|------|------|------|
| 完成率差异 | Logistic回归（控制任务难度、词数、os） | OR, 95% CI, p |
| 步数差异 | 负二项回归 | 预期步数比率 |
| 冗余比例差异 | Tobit回归（因变量0-1截断） | 系数, p |
| 首次正确率 | Logistic回归 | OR |
| 错误类型分布 | 卡方检验 | 列联表 |

### 第三步：验证表述细化程度的非线性分析

**细化程度操作化**：验证相关词数 / 指令总词数

**模型**：
```
task_completed ~ poly(verification_density, 2) + task_difficulty + word_count + os
```

检验二次项是否显著，以判断是否存在倒U形关系。

### 第四步：验证标准位置的影响

**分析**：验证表述出现在指令的开头、中间还是末尾，对效果有何差异？

方法：用正则定位验证关键词在指令中的相对位置（起始25%/中间50%/末尾25%），然后比较三组的效果差异。
